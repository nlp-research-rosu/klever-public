## 2. Program fidelity and candidate-versus-canonical checks

### Source contract

For every square `N × N` grid with `N >= 2` containing each integer `1..N²` exactly once, and every positive integer `k`, return the lexicographically least sequence of cell values among all grid walks that visit exactly `k` cells and move only across shared edges.

The mathematical characterization used by both Python implementations is valid. Every lexicographically least path must start at the unique cell containing `1`. Its second element, when present, must be the least value in a neighboring cell. From that neighbor the path can return to `1`, and repeating these two cells gives the lexicographically least continuation. Thus the result alternates `1` and the least neighbor of `1`.

### Python implementation

`/candidate/solution.py` scans the whole grid for the unique `1`, computes the minimum of its in-bounds neighbors, and appends the alternating sequence for `range(k)`. On the intended domain, the implementation agrees with the trusted canonical and the contract. It does not rely on a fixed grid size.

Using the trusted translator:

```text
python3 py2mpy.py solution.py > regenerated-solution.mpy
```

exited 0, and `cmp -s regenerated-solution.mpy solution.mpy` exited 0. Both files hash to `3c8e5ab1a1ba5eda4bf0804065e28ff8ceaef37d8ec61ebb04fd1ac3fe4cc9d3`. See [translation-fidelity.log](evidence/translation-fidelity.log).

### Independent differential test

[differential_test.py](evidence/differential_test.py) imports the trusted canonical and the generated entry point independently. It exercises:

- both documented examples;
- `N = 2`, `k = 1`;
- corner, edge, and interior placements of `1`;
- odd and even `k`;
- all 24 permutations of a 2×2 grid at `k ∈ {1,2,3,4,5,9}`;
- 40 seeded random permutations for every `N = 2..8`, with `k = 1..15`;
- out-of-domain empty-grid and `k = 0` characterization.

There were 431 valid-domain cases, zero canonical/generated mismatches, 202 cases checked against a separately implemented exhaustive-walk oracle, and zero oracle mismatches. Empty inputs were reported only as out-of-contract characterization, not used as a correctness obligation. Command, status, and results are in [differential-test.log](evidence/differential-test.log). Stage 2 passes.

## 4. Adequacy and real-program pinning

### Plain-language meaning of each claim

1. **Append-loop claim** (`/candidate/spec.k:8`). Assume `0 <= I < K`; the current local scope contains exactly `i`, `path`, and `neighbor`; `path` points to heap list `P`; and `neighbor` is arbitrary integer `N`. Executing the internal `#loop(rangeObj(I,K,1), ...)` consumes the loop, changes `i` to `K-1`, preserves `neighbor`, and changes the heap list to `minPathBuild(P,I,K,N)`.

2. **First example** (`/candidate/spec.k:36`). Loading the submitted module and calling `minPath([[1,2,3],[4,5,6],[7,8,9]],3)` returns `ref(0)`, whose heap object is exactly `[1,2,1]`, with normal scope, stack, return, exception, allocation, and exit cells.

3. **Second example** (`/candidate/spec.k:72`). Loading the module and calling `minPath([[5,9,3],[4,1,6],[7,8,2]],1)` returns a heap list exactly `[1]`, with the other observable cells normal.

4. **Symbolic 2×2 claim** (`/candidate/spec.k:105`). For four pairwise-distinct integers `A,B,C,D`, each in `1..4`, loading the module and calling `minPath([[A,B],[C,D]],4)` returns exactly `[1,M,1,M]`, where `M` is the lesser neighbor of the unique `1`.

The postconditions are result-constraining: each function-entry claim fixes the returned reference, exact list contents, allocation counter, environment, scope, stack, return state, exception state, and exit code. The loop claim fixes the updated heap sequence and loop variable. None has a free result variable, tautological implication, or unconstrained oracle.

### Material adequacy failure

The source domain is all `N >= 2`, all valid permutations of `1..N²`, and every positive `k`. The proof does not quantify over that domain:

- the only symbolic **full-program** theorem fixes `N = 2`;
- it also fixes `k = 4`;
- the two `N = 3` theorems are single concrete examples;
- there is no full-program theorem for arbitrary `N`, arbitrary location of `1`, arbitrary in-bounds neighbor set, or arbitrary positive `k`;
- the append-loop theorem begins only after the scan and neighbor computation have already produced arbitrary `N`;
- more importantly, its local `scope` map contains exactly three bindings. The real function frame at the final loop also contains `grid`, `k`, `n`, `row`, `column`, loop variables, and possibly `value`. Therefore that circularity does not match the real full-program loop head and cannot lift the fixed-`k` full-program claim to arbitrary `k`.

The separate loop theorem is legitimate partial progress, but it does not connect the general path-length result to a general full execution. Stage 4 therefore fails intent adequacy.
