## What is proven

Under the supplied `MPY` reference semantics, the translated
`sum_squares` function is partially correct: for every finite semantic list
`list(VS)`, if the call terminates, its returned integer is
`sumCeilSquares(VS)`, where

```text
sumCeilSquares(.ValSeq) = 0
sumCeilSquares(vCons(V, VS))
  = ceilF(V) * ceilF(V) + sumCeilSquares(VS)
```

For finite Python integer and finite binary64-float elements, the supplied
semantics intends `ceilF` to be `math.ceil`. Thus, conditional on that supplied
primitive contract, the returned integer is the sum of the squares of the
elementwise ceilings requested by `prompt.py`.

This is a partial-correctness result in the Kit sense. It is not a separate
liveness theorem.

## Formal claims

`SPEC.loop-inv` starts at the exact `#loop` generated for the `for` statement.
The local frame contains only `lst`, `number`, `rounded`, and `total`, with
plain-function parent `0`. Starting with accumulator `ACC` and remaining
sequence `VS`, it reaches the same continuation with:

```text
total = ACC + sumCeilSquares(VS)
```

The final values of the unobserved loop temporaries `number` and `rounded` are
existential. `lst`, the frame parent, environment, continuation, and all other
framed configuration cells are preserved.

`SPEC.sum-squares` starts from the full initial MPY configuration, expands
`solutionProgram`, loads its definition, resolves and calls `sum_squares` on
`list(VS)`, executes the function body, and returns
`sumCeilSquares(VS)`. The result, empty heap, environment, heap location, stack,
return state, exception state, and exit code are constrained by the claim. The
post-load module map is intentionally existential because module binding is not
an observable named by the HumanEval contract.

## Trust boundary

- `reference-semantics/` is the fixed operational theory trusted by the
  theorem. All positive claims depend on it; it affects values, state, control,
  exceptions, and the meaning of termination.
- `ceilF(Val)` in `reference-semantics/semantics/float.k` is the specific
  result-bearing trusted primitive. Under symbolic Haskell execution it remains
  opaque for a symbolic element; concrete rules implement the Int and Float
  cases for LLVM. Both claims depend on it. The formal theorem proves the fold
  structure for whatever value this fixed primitive returns; mathematical
  ceiling is conditional on its supplied contract.
- `py2mpy.py` is the fixed source-to-constructor translator. It affects program
  identity. `check_program_identity.py` proves only that the K AST constant
  equals its generated output, not that the translator is a verified model of
  all CPython parsing.
- K v7.1.293, its Haskell/LLVM backends, and their solver/runtime are trusted
  proof infrastructure.

## Empirically supported facts

`smoke.py` uses LLVM concrete execution for the five prompt examples and the
empty list; all assertions terminate with `NoExc` and exit code 0.

`differential_test.py` uses an independently constructed ceiling oracle:
`Fraction(value)` followed by integer numerator/denominator ceiling. It covers
the prompt examples, empty input, exact integers, values immediately around
negative and zero boundaries, and 1,000 deterministic random lists drawn from
400 values in `[-100, 100]`. It reports 1,008 cases and zero mismatches. This is
finite evidence for the concrete primitive and implementation, not a universal
equivalence proof.
