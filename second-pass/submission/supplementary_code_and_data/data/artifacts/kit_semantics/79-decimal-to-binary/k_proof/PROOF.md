## What is proven

Under the supplied `MPY` semantics, for every symbolic mathematical integer
`N >=Int 0`, calling the exact translated `decimal_to_binary` closure terminates
in the proof's final state only with a string satisfying `decimalResultRel(N,
CODES)`.  That relation requires:

- leading ASCII codes `100, 98` (`"db"`);
- for zero, the middle digit `48` (`"0"`);
- for a positive value, the unique sequence generated by repeatedly prepending
  code `48 + (N mod 2)` and replacing `N` by floor division by two; and
- trailing ASCII codes `100, 98` (`"db"`).

This is a symbolic, unbounded partial-correctness theorem.  It is not a proof
over finitely many sizes.  Termination is not part of K reachability, but the
usual ranking argument applies: on every positive iteration,
`0 <= N // 2 < N`, so a nonnegative input reaches zero.

## Formal claims

`spec.k` contains:

1. `SPEC.binary-loop`, a circularity at the fixed semantics' actual
   `#while(...)` loop head.  From any `N >= 0` and any string-code accumulator
   `ACC`, it reaches `decimal = 0` and an existential `OUT` satisfying
   `binRel(N, ACC, OUT)`.
2. `SPEC.decimal-to-binary`, the target theorem.  It begins with a real
   `Call(Name("decimal_to_binary"), ...)`, pins that name to the exact body in
   `solution.mpy`, executes lookup, binding, initialization, the loop, return,
   frame pop, and state restoration, and constrains the returned codes with
   `decimalResultRel`.

The observable result is the returned `str(CODES)`.  The claims also pin
environment, scopes, scope allocator, heap, heap allocator, stack, return,
exception, and exit-code cells.  Function-local variables disappear when the
callee frame is popped, as required by the fixed call semantics.

## Proof-extension inventory

There are no operational bridges, no rules that intercept Python syntax, no
opaque result-bearing symbols, no trusted primitives added by this proof, and
no simplification lemmas.

### `binRel`

- **Class:** definitional summary.
- **Role/value influence:** defines the exact digit sequence used by the loop
  invariant and therefore influences the returned value.
- **Domain:** all `Int`; the mutually disjoint guards are `N == 0`, `N > 0`,
  and `N < 0`, which are exhaustive.
- **Definition:** zero equates `ACC` and `OUT`; positive `N` recurses on
  `(N - pyMod(N, 2)) / 2` with code `48 + pyMod(N, 2)` prepended; negative
  `N` is false.
- **Descent/consistency:** for positive `N`, the recursive integer is
  nonnegative and strictly smaller.  No guarded cases overlap.
- **Matched context/state footprint:** pure `Bool` terms only; no computation,
  continuation, binding, or state cell is matched or replaced.
- **Justification:** this is the standard repeated-division definition of
  base-2 digits, and its positive equation is exactly the program loop's two
  state updates.  `SPEC.binary-loop` machine-checks the base and inductive
  obligations against fixed execution.
- **Dependents:** both claims.

### `decimalTailRel` and `decimalResultRel`

- **Class:** definitional summaries.
- **Role/value influence:** state the HumanEval formatting property.
- **Domain:** all `Int` and all `IntSeq`.
- **Coverage/overlap:** `decimalTailRel` uses the same disjoint sign partition.
  `decimalResultRel` accepts precisely a leading `iCons(100, iCons(98, ...))`;
  its `[owise]` case is the disjoint complement.
- **Definition:** zero requires `"0db"` after the leading wrapper; positive
  inputs apply `binRel` with the trailing `"db"` as the initial accumulator;
  `decimalResultRel` requires the leading `"db"`.
- **Matched context/state footprint:** pure Boolean terms; no operational
  cells or control effects.
- **Justification:** exhaustive formatting equations; the target claim
  machine-checks their connection to the exact returned string.
- **Dependents:** `SPEC.decimal-to-binary`.

### `SPEC.binary-loop`

- **Class:** derived reachability lemma/circularity.
- **Matched context:** exact `#while` term and body with an arbitrary preserved
  continuation; environment `1`; a module scope containing only the function
  binding; fixed builtins scope; exact local keys `binary` and `decimal`;
  `scopeLoc = 2`; empty heap; `heapLoc = 0`; arbitrary preserved stack;
  `noRet`, `NoExc`, and exit code `0`.
- **State footprint:** reads and writes the two local variables; reads the
  fixed builtin binding for `chr`; preserves all other matched cells.
- **Control/value justification:** fixed semantics executes lookup, `%`, `+`,
  `chr`, string concatenation, assignment, `//`, and loop control.  No rule
  skips any of these operations.  The result relation is threaded through the
  circularity rather than asserted about a completed result.
- **Dependents:** the target entry claim.

### `SPEC.decimal-to-binary`

- **Class:** target reachability claim, not an added semantic rule.
- **Matched context:** exact named binding, parameter list, function body,
  argument, module/builtin scopes, and complete initial state.
- **State/control:** all function execution and frame lifecycle use fixed
  semantics.
- **Validation:** the exact body is visible in `solution.mpy`; the AST identity
  check confirms `smoke.py` executes the same function body.  The separate
  body mutation changes `48 + n % 2` to `49 + n % 2` and is rejected.

## Gate results

### Gate A — PASS

- The target executes the exact program-defined closure under fixed semantics.
- No proof rule replaces lookup, evaluation, loop control, return, frame
  handling, state updates, exceptions, or values.
- All definitional equations have exhaustive, disjoint guards and a
  well-founded positive recursion.
- The module scope in the loop theorem is pinned so `chr` cannot be shadowed;
  lookup therefore reaches the fixed builtin binding.
- The satisfiable zero witness and false-result mutation establish
  non-vacuity.
- The material body mutation is rejected and produces a different concrete
  fixed-semantics result.

### Gate B — PASS

The prompt's material domain is arbitrary nonnegative decimal integers:
`N:Int` with `N >=Int 0`.  The theorem is symbolic and unbounded over that
entire domain.  The middle-character recurrence produces only codes `48` and
`49`, and `decimalResultRel` fixes both `"db"` wrappers and the zero case.

The summary-to-property bridge is the definition itself, with a
well-founded induction on `N`: for positive `N`, let
`Q = N // 2` and `R = N mod 2`.  Then `N = 2*Q + R`,
`R` is `0` or `1`, and the recurrence prepends code `48 + R` to the
accumulator before continuing from the strictly smaller `Q`.  The induction
hypothesis therefore yields the ordinary most-significant-first base-2 digits
of `N`; the explicit zero equation yields the single digit `"0"`.  This also
establishes uniqueness of every accepted result sequence.

Negative integers are excluded because the stated output alphabet permits only
binary digits between the wrappers and supplies no sign representation.
Non-integer inputs are outside the prompt's decimal-integer operation (and
Python's binary-integer conversion contract).  The supplied model uses
unbounded mathematical integers, matching Python's arbitrary-precision integer
behavior for this computation; all produced text is ASCII, so the semantics'
ASCII string boundary does not narrow any result.

### Gate C — PASS

All commands, probes, inputs, outputs, and assumptions are reproducible in
existing artifacts.  Formal proof, mathematical interpretation, empirical
evidence, and exclusions are separated here.
