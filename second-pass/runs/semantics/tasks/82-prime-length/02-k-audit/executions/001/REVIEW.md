# Independent adversarial audit: 82-prime-length

The candidate is **not a legitimate partial-correctness proof of the requested
program**. Fresh reconstruction confirms that all three submitted reachability
claims print `#Top`, but the length-at-least-two entry claim does not constrain
the function's return value. It stops at a proof-only, non-Boolean marker
created by an operational bridge that preempts every real `While`, discards the
continuation, and clears control/state cells. The separately proved internal
loop theorem is never connected to that marker or to the entry claim.

Audit environment: `SUPPLIED_SEMANTICS`; K v7.1.337; Python 3.10.12. Candidate
files were read only. Source reconstruction and all generated artifacts were
performed under `/tmp/audit-work/82`; reviewer scripts and bounded logs are in
[`evidence/`](evidence/). Tool versions and the evidence manifest are recorded
in [`32_tool_versions.log`](evidence/32_tool_versions.log) and
[`31_evidence_manifest.log`](evidence/31_evidence_manifest.log).

## 2. Program fidelity and candidate-versus-canonical checks

### Contract and intended domain

For every Python string, return `True` exactly when its Python length is a prime
integer, and otherwise return `False`. The documented examples require lengths
5 and 7 to be true and length 6 to be false. The trusted canonical program
computes `l = len(string)`, rejects 0 and 1, tests every divisor in
`range(2,l)`, rejects on the first exact divisor, and otherwise returns true.

`solution.py` implements the same behavior with a `while`: it rejects
`n < 2`, starts `divisor = 2`, tests `n % divisor == 0`, increments the divisor,
and returns true only after all candidates below `n` have been rejected. On the
intended domain it has the same branch boundaries and result as the canonical
implementation.

### Translator identity

The trusted `/reference/py2mpy.py` regenerated the scratch copy of
`solution.py` successfully, and the regenerated bytes are identical to the
submitted `solution.mpy`. Commands and statuses are in
[`09_regenerate_solution.log`](evidence/09_regenerate_solution.log),
[`10_solution_mpy_identity.log`](evidence/10_solution_mpy_identity.log), and
the empty diff in [`11_solution_mpy_diff.log`](evidence/11_solution_mpy_diff.log).

### Independent differential execution

The reviewer-authored
[`differential_test.py`](evidence/differential_test.py) imports the trusted
canonical and candidate modules independently and also uses a separate
square-root-bound primality oracle. Its 435 cases include:

- all four documented examples;
- empty and length-one cases;
- loop-not-entered length 2;
- prime-loop and first/later-divisor boundaries (3, 4, 5, 6, 9, 11, 12);
- Unicode, combining-code-point, embedded-NUL, and content-varied strings;
- every length from 0 through 256; and
- 160 deterministic seeded strings with lengths through 400.

Every input, its length/hash, and all three results are preserved in
[`12_differential.log`](evidence/12_differential.log). It reports 435 cases,
suite SHA-256
`fc87b249224be0042552ed99105f82ee22a41602ffc11b3c9536bbadf146810f`,
and zero mismatches. This is strong finite fidelity evidence, not a substitute
for a K reachability proof.

**Stage 2 result:** program and translated AST fidelity pass.

## 4. Adequacy and real-program pinning

### Plain-language claim accounting

| Claim | Preconditions | What its postcondition actually says |
|---|---|---|
| `prime-length-small` | Directly invoke the proof-local `primeLengthClosure` on `str(CS)` from the initial cells; structural length is 0 or 1. | The call returns Boolean `false`. |
| `prime-length-setup` | Directly invoke the same proof-local closure; structural length is at least 2. | Execution becomes the proof-only K item `#primeLoopEntry(isLen(CS),2)` while environment, scopes, stack, and return state are reset. It says nothing about a Boolean return. |
| `divisor-loop` | Start at the internal fixed-semantics `#while` with exact loop body and trailing `Return(true) ~> #endcall`; live integers are `n=N`, `divisor=D`; `D>=2`; exact callee frame/cells are present. | The internal loop and return produce `noDivisorsFrom(N,D)` and pop the frame. |

All preconditions are satisfiable. Examples are:

- small: `CS=.IntSeq` (empty string);
- setup: any two-code sequence, for example codes for `"ab"`;
- loop: `N=5`, `D=2`, any `string` value, the displayed builtins/module/callee
  scopes, and the displayed single call frame.

Concrete substitutions are preserved in
[`22_ground_comparison.log`](evidence/22_ground_comparison.log). Empty and
length-one inputs produce the claimed `false` in both Python implementations.
For lengths 2, 4, and 5, the setup RHS is respectively
`#primeLoopEntry(2,2)`, `#primeLoopEntry(4,2)`, and
`#primeLoopEntry(5,2)`—not the Python Booleans `true`, `false`, and `true`.
For the independent internal-loop claim, `noDivisorsFrom(N,2)` evaluates to
the same Boolean as both implementations for the sampled `N=2,4,5,9`.

### Material pinning failures

1. **No high-input result theorem.** The only entry claim covering every
   intended string of length at least two ends at `#primeLoopEntry`. This sort
   is `KItem`, not `Bool`, and the marker has no rule that produces
   `noDivisorsFrom` or a return value.
2. **No composition with the loop theorem.** The setup RHS is not the loop
   claim's LHS. It has already discarded the `#while`, trailing return,
   callee scope, and frame. The claims live in separately selected spec modules;
   neither is compiled as a connection rule for the other. There is no
   reachability claim from `#primeLoopEntry(N,D)` to the internal loop state or
   to `noDivisorsFrom(N,D)`.
3. **The submitted module is not executed by an entry claim.** Entry claims
   construct `primeLengthClosure` directly instead of loading the submitted
   `solution.mpy` `Module`, defining `prime_length`, resolving that binding,
   and calling it. The proof-local `primeBody` is constructor-for-constructor
   identical to the regenerated AST, so this manual pin is credible evidence,
   but no K connection theorem formally pins the file/module execution.
4. **No formal primality postcondition at entry for `n>=2`.**
   `noDivisorsFrom(N,2)` is a truthful mathematical characterization of
   primality for `N>=2`, but only the isolated internal loop reaches it.

The result-constraining small claim and sound internal-loop claim cannot repair
the missing top-level result theorem over the majority of the intended domain.

**Stage 4 result:** fail. The submitted claims do not prove the requested
partial-correctness result for lengths at least two and do not fully pin actual
module execution.

## 5. Rule-by-rule static soundness review

### Exhaustive inventory

[`13_k_inventory.log`](evidence/13_k_inventory.log) enumerates every local K
sentence with file, line span, normalized text, attributes, and class. It
contains 1,115 sentences, including:

- 704 rules: 595 ordinary, 48 priority, 35 concrete, 26 `owise`;
- 232 syntax sentences: 149 function, 79 ordinary, 4 macro;
- five contexts, one configuration, and three claims; and
- no simplification rules, `functional` declarations, or aliases.

Exact per-file counts are in
[`27_inventory_by_file.log`](evidence/27_inventory_by_file.log). All 25
explicit symbolic/opaque declarations are in
[`28_opaque_inventory.log`](evidence/28_opaque_inventory.log): 22 float
symbols, `sortVS`, `sortKeyVS`, and `md5hexCodes`. None is reachable from the
submitted program or proof claims.

The per-file and per-rule disposition is documented in
[`static_soundness_review.md`](evidence/static_soundness_review.md), and every
submitted syntactic construct is mapped to its declaration/rules in
[`used_construct_map.md`](evidence/used_construct_map.md).

On the used fixed-semantics path, configuration, lookup, left-to-right
evaluation, builtin `len`, integer comparison/modulo/addition, assignment,
while control, calls, returns, and frame cleanup are consistent. No allocation
or heap mutation occurs. The divisor is initialized to 2 and only increases, so
the `%` rule never sees divisor zero. Supplied priority/ref rules are
sort-disjoint on this path. Compiler-reported totality gaps concern unused
`mapStrVS`, generic float conversions, `joinCodes` on non-string internal
values, and out-of-bounds `valSeqAt`; these are recorded as unused trust/evidence
gaps rather than mislabeled as false rules.

### Proof-local definitions

The equations for `primeLoopBody`, `primeBody`, and `primeLengthClosure` are
truthful constructor abbreviations. The three guarded equations for
`noDivisorsFrom` are mutually exclusive on the used domain, cover
base/divisible/nondivisible cases, and recurse by increasing `D`. They do not
smuggle the task answer into program execution.

The three capture rules are different. The first is:

```text
While(_C,_B) => Name("n") ~> #capturePrimeLoopN ... [priority(1)]
```

It preempts the supplied `While => #while` rule for every while statement,
with no condition/body/binding/continuation guard. The final capture rule
rewrites

```text
D ~> #capturePrimeLoopD(N) ~> _REST
```

to `#primeLoopEntry(N,D)`, discards `_REST`, clears all scopes and the stack,
and resets environment/scope/return cells. No bridge-free universal connection
theorem was submitted. The matched context is strictly broader than any
justification.

### Required false-conclusion witness

The full symbolic and concrete witness is
[`bridge_witness.md`](evidence/bridge_witness.md). On the actual intended input
`"ab"` (length 2), fixed semantics skips the loop and returns `true`. In the
reviewer concrete suite, fixed LLVM semantics completes that assertion and all
later assertions (`17_krun_audit_concrete.log`). The same submitted program
under the bridge-enabled proof definition stops at:

```text
<k> #primeLoopEntry ( 2 , 2 ) ~> .K </k>
<env> 0 </env>
<scopes> .Map </scopes>
<stack> .List </stack>
```

and never executes the remaining continuation
([`26_krun_bridge_enabled.log`](evidence/26_krun_bridge_enabled.log)). Thus the
bridge enables the false execution conclusion “the real call reaches a
non-Boolean marker with its caller/program continuation and scopes discarded”
where fixed semantics returns Boolean true and preserves caller state. For
length 4, fixed semantics enters the body and returns false; the bridge instead
produces `#primeLoopEntry(4,2)` without testing divisibility. An independent
continuation witness shows it can also discard an assignment immediately after
an unrelated false-condition while.

These rules are not a harmless mathematical summary or a low-level primitive.
They replace a program-defined, result-bearing computation and change control
and every relevant state cell. The `prime-length-setup` `#Top` depends on this
bridge.

**Stage 5 result:** fail. The proof extension bypasses real loop execution and
enables a demonstrably false fixed-semantics trace.

## 7. Proven versus assumed accounting

### What the successful reachability proofs establish

Conditioned on the supplied K semantics and candidate proof rules:

1. the directly constructed exact-body closure returns false for structural
   string lengths 0 and 1;
2. for structural lengths at least 2, bridge-instrumented execution reaches a
   marker containing the live length and initial divisor, while destructively
   resetting state; and
3. from an exact internal `#while` call-frame state with `D>=2`, fixed loop
   execution returns the recursively defined `noDivisorsFrom(N,D)`.

They do **not** establish that an actual `solution.mpy` entry call returns
`noDivisorsFrom(len(string),2)` for length at least 2, that it returns a Boolean
matching primality over the full domain, or that the setup and loop claims
compose.

### Trust ledger

| Boundary | Dependents | Assessment |
|---|---|---|
| K v7.1.337 parser, Haskell/LLVM backends, SMT/builtin Int/Bool/Map operations | All dynamic evidence and proofs | Ordinary unavoidable tool trust; versions and exact commands recorded. |
| Byte-identical supplied MPY semantics | All K execution | Authorized supplied semantics. Used call/len/int/while/return path was statically reviewed and concretely exercised. |
| Trusted translator plus byte identity | `solution.py` to `solution.mpy` bridge | Acceptable source-fidelity evidence. It does not connect the proof-local closure to module loading by itself. |
| Manual equality of `primeBody`/`primeLoopBody` constructors to regenerated AST | Entry and loop claims | Credible audited bridge, but informal because no K connection theorem executes the submitted module. |
| Recursive `noDivisorsFrom` equations and ordinary number theory | Internal loop result | Truthful and formally used by the internal loop proof. Equivalence to primality at `D=2,N>=2` is straightforward mathematics, but no high-entry claim reaches it. |
| 25 opaque float/sort/MD5 symbols | None of these claims | Explicit supplied trust boundaries, acceptable here only because unreachable. Full list is in `28_opaque_inventory.log`. |
| Differential/canonical testing | Python intent bridge only | 435-case finite support; not a universal K theorem and not used as a proof substitute. |
| Capture operational bridge | `prime-length-setup` | Illegitimate. It affects control, state, and the only high-input postcondition; no connection theorem exists and fixed/extended execution disagrees concretely. |
| Termination | Not established by reachability logic | The submitted proof is partial-correctness only. Python/code inspection supports termination, but that cannot fill the missing result theorem. |

### Decision

Fresh builds and `#Top` results are genuine, and the Python implementation is
faithful. Nevertheless, the candidate proves only the small branch and an
isolated internal loop theorem. The entry claim covering all lengths at least
two is non-result-constraining, cannot compose with the loop theorem, does not
execute the submitted module, and closes through an operationally unsound loop
interception with a concrete intended-domain counterexample. This meets
multiple independent `FAIL / NOT_LEGIT` criteria.

VERDICT: FAIL
LEGITIMACY: NOT_LEGIT
