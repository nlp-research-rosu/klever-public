# Independent adversarial audit — 160-do-algebra

Generation condition: `semantics`  
Rendered semantics mode: `SUPPLIED_SEMANTICS`

## Executive decision

The reconstructed K claims are real, non-vacuous partial-correctness theorems
about the submitted `solution.mpy`: all ten close independently, the launcher
loads the exact submitted AST, and no candidate-local rule replaces
`_evaluate` with an oracle or a task-answer shortcut.

They are not, however, a proof of `do_algebra` on the prompt's intended input
domain. `spec.k` enumerates ten fixed operator-list shapes, with several
fixed operands, and contains no entry claim quantified over an arbitrary
contract-valid operator/operand list. Contract-valid examples such as two
additions, an exponentiation other than `2 ** 5`, most mixed expressions, and
all sufficiently long expressions satisfy no claim. That is a material
adequacy failure, not merely thin supporting evidence. The candidate therefore
does not contain the requested whole-program partial-correctness proof.

All candidate files were treated as untrusted. Candidate compiled artifacts,
caches, scripts, and claimed outputs were not used as proof evidence.

## 2. Program fidelity and candidate-versus-canonical checks

### Natural-language contract

From trusted `/reference/prompt.py` and `/reference/canonical.py`, `do_algebra`
takes:

- at least one operator from `+`, `-`, `*`, `//`, `**`;
- at least two non-negative integer operands;
- exactly one more operand than operator;
- and returns the Python evaluation of the interleaved expression, including
  Python precedence, left associativity for `+`, `-`, `*`, `//`, and right
  associativity for `**`.

The prompt does not exclude a zero divisor. The canonical implementation raises
`ZeroDivisionError` for such an expression instead of returning an integer.
Accordingly, a normal-return theorem must either model that exceptional path or
state a sufficient nonzero-divisor precondition.

### Source algorithm

`solution.py` implements a precedence parser by recursive interval evaluation:

- level 0 scans from right to left for `+`/`-`, producing left associativity;
- level 1 scans from right to left for `*`/`//`;
- level 2 scans from left to right for `**`, producing right associativity;
- level 3 returns the selected operand.

This is a different algorithm from the canonical string construction plus
`eval`, which is acceptable if behavior agrees.

```text

```

exited 0. The result is byte-identical to `/candidate/solution.mpy`; both have

`4e1c9df6f7e7d5229be2910bf7215954e8c7789d9603370de5ca7c5b1c2306d4`.
See [02_fidelity.log](evidence/02_fidelity.log).

### Independent differential execution

[02_differential.py](evidence/02_differential.py) independently imports the
trusted canonical entry point and candidate entry point. It runs:

- minimum two-operand cases for all five operators;

- both scan directions and all associativity/precedence boundaries;
- the all-precedence expression;
- 400 deterministic generated cases using lengths 1 through 5, all operator
  tokens, and operands 0 through 8. Generated cases contain at most one
  exponentiation to bound arithmetic size; adjacent exponentiation is covered
  separately.

The exact command exited 0 with:


See [02_differential.log](evidence/02_differential.log) and the complete
[02_differential-results.json](evidence/02_differential-results.json). This is
strong finite fidelity evidence, not a universal equivalence proof.

### Candidate-local rule decisions

`verification.k` adds eight rules:

1. `solutionProgram` is a macro definition. Fresh macro expansion is identical
   to parsed `solution.mpy`; it does not replace execution.
2. Five operator-token macros map to the exact ASCII code sequences for `+`,
   `-`, `*`, `//`, and `**`. They are disjoint and mathematically exact.
3. `floorQuot(A,B) = (A - pyMod(A,B))/B` is a definitional postcondition
   helper. It does not replace program execution and is correct for every
   positive divisor used by a claim.
4. `runDoAlgebra` is a launcher that schedules
   `#loadAll(solutionProgram)` followed by an ordinary `do_algebra` call.

There is no candidate-local opaque symbol, priority rule, simplification rule,
auxiliary claim, circularity, return bridge, or oracle. No task answer is
encoded into execution semantics.

One narrow declaration defect remains: `floorQuot` is marked unguarded
`[function, total]`, including `B=0`, while its RHS contains undefined modulo
and division by zero. All actual uses have positive divisors. I found no false
conclusion witness enabled on a claim path, so I do not label this rule
unsound; it is an over-broad totality/evidence gap that should be repaired with
a nonzero guard or narrowed sort/domain.

No inventoried rule is claimed here to enable a false result on an intended
claim input, so there is no unsupported unsoundness accusation requiring a
false-conclusion witness. The final rejection instead rests on the explicit
coverage witness in Stage 4.

## 7. Proven versus assumed accounting

### Precisely proven

Under the exact supplied MPY semantics and K's builtin theories, the submitted
translated program, started in the specified clean configuration, produces the
explicit results in the ten entry-claim rows of Stage 4 whenever their
preconditions hold. The proof executes the exact `_evaluate` and `do_algebra`
bodies. It also constrains all listed observable cells and rejects an off-by-one
result.

That statement is limited to the ten input shapes. It is not a theorem about
all prompt-valid operator/operand lists.

### Gate accounting and verdict rationale

- Fresh reconstruction: **pass** for all ten stated claims.
- Real-program pinning and non-vacuity: **pass** for all ten stated claims.
