     1	def skjkasdkd(lst):
     2	    largest = 0
     3	    number = 0
     4	    divisor = 2
     5	    prime = False
     6	    digit_total = 0
     7	    for number in lst:
     8	        if number > largest:
     9	            divisor = 2
    10	            prime = number >= 2
    11	            while prime and divisor * divisor <= number:
    12	                if number % divisor == 0:
    13	                    prime = False
    14	                divisor += 1
    15	            if prime:
    16	                largest = number
    17	    while largest > 0:
    18	        digit_total += largest % 10
    19	        largest //= 10
    20	    return digit_total

     5	Basic Builtin Types in K
     6	========================
     7	
     8	A major piece of the K prelude consists of a series of modules that contain
     9	implementations of basic data types and language features in K. You do not need
    10	to require this file yourself; it is required automatically in every K
    11	definition unless `--no-prelude` is passed to kompile. K may not work correctly
    12	if some of these modules do not exist or do not declare certain functions.
    13	
    14	Note that some functions in the K prelude functions are not total, that is,
    15	they are not defined on all possible input values. When you invoke such a
    16	function on an undefined input, the behavior is undefined. In particular, when
    17	this happens, interpreters generated by the K LLVM backend may crash.
    18	
    19	```k
    20	requires "kast.md"
    21	```
    22	
    23	Default Modules
    24	---------------
    25	
    26	K declares certain modules that contain most of the builtins you usually want
    27	when defining a language in K. In particular, this includes integers, booleans,
    28	strings, identifiers, I/O, lists, maps, and sets. The `DOMAINS-SYNTAX` module
    29	is designed to be imported by the syntax module of the language and contains
    30	only the program-level syntax of identifiers, integers, booleans, and strings.
    31	The `DOMAINS` module contains the rest of the syntax, including builtin
    32	functions over those and the remaining types.
    33	
    34	Note that not all modules are included in DOMAINS. A few less-common modules
    35	are not, including `ARRAY`, `COLLECTIONS`, `FLOAT`, `STRING-BUFFER`, `BYTES`,
    36	`K-REFLECTION`, `MINT`.
    37	
    38	```k
    39	module DOMAINS-SYNTAX
    40	  imports SORT-K
    41	  imports ID-SYNTAX
    42	  imports UNSIGNED-INT-SYNTAX
    43	  imports BOOL-SYNTAX
    44	  imports STRING-SYNTAX
    45	endmodule
    46	
    47	module DOMAINS
    48	  imports DOMAINS-SYNTAX
    49	  imports INT
    50	  imports BOOL
    51	  imports STRING
    52	  imports BASIC-K
    53	  imports LIST
    54	  imports K-IO
    55	  imports MAP
    56	  imports SET
    57	  imports ID
    58	  imports K-EQUAL
    59	endmodule
    60	```

    62	Arrays
    63	------
    64	
    65	Provided here is an implementation for fixed-sized, contiguous maps from `Int`
    66	to `KItem`. In some previous versions of K, the `Array` type was a builtin type
    67	backed by mutable arrays of objects. However, in modern K, the `Array` type is
    68	implemented by means of the `List` type; users should not access this interface
    69	directly and should instead make only of the functions listed below. Users of
    70	this module should import only the `ARRAY` module.
    71	
    72	```k
    73	module ARRAY-SYNTAX
    74	  imports private LIST
    75	
    76	  syntax Array
    77	```
    78	
    79	### Array lookup
    80	
    81	You can look up an element in an `Array` by its index in O(log(N)) time. Note
    82	that the base of the logarithm is a relatively high number and thus the time is
    83	effectively constant.
    84	
    85	```k
    86	  syntax KItem ::= Array "[" Int "]" [function]
    87	```
    88	
    89	### Array update
    90	
    91	You can create a new `Array` with a new value for a key in O(log(N)) time, or
    92	effectively constant.
    93	
    94	```k
    95	  syntax Array ::= Array "[" key: Int "<-" value: KItem "]" [function, symbol(_[_<-_])]
    96	```
    97	
    98	### Array reset
    99	
   100	You can create a new `Array` where a particular key is reset to its default
   101	value in O(log(N)) time, or effectively constant.
   102	
   103	```k
   104	  syntax Array ::= Array "[" Int "<-" "undef" "]" [function]
   105	```
   106	
   107	### Multiple array update
   108	
   109	You can create a new `Array` from a `List` `L` of size `N` where the `N`
   110	elements starting at `index` are replaced with the contents of `L`, in
   111	O(N*log(K)) time (where K is the size of the array), or effectively linear.
   112	Having `index + N > K` yields an exception.
   113	
   114	```k
   115	  syntax Array ::= updateArray(Array, index: Int, List) [function]
   116	```
   117	
   118	### Array fill
   119	
   120	You can create a new `Array` where the `length` elements starting at `index`
   121	are replaced with `value`, in O(length*log(N)) time, or effectively linear.
   122	
   123	```k
   124	  syntax Array ::= fillArray(Array, index: Int, length: Int, value: KItem) [function]
   125	```
   126	
   127	### Array range check
   128	
   129	You can test whether an integer is within the bounds of an array in O(1) time.
   130	
   131	```k
   132	  syntax Bool ::= Int "in_keys" "(" Array ")" [function, total]
   133	```
   134	
   135	```k
   136	endmodule
   137	
   138	module ARRAY-IN-K [private]
   139	  imports public ARRAY-SYNTAX
   140	  imports private LIST
   141	  imports private K-EQUAL
   142	  imports private INT
   143	  imports private BOOL
   144	```
   145	
   146	### Array creation
   147	
   148	You can create an array with `length` elements where each element is
   149	initialized to `value` in O(1) time. Note that the array is stored in a manner
   150	where only the highest element that is actually modified is given a value
   151	in its internal representation, which means that subsequent array operations
   152	may incur a one-time O(N) resizing cost, possibly amortized across multiple
   153	operations.
   154	
   155	```k
   156	  syntax Array ::= makeArray(length: Int, value: KItem) [function, public]
   157	```
   158	
   159	### Implementation of Arrays
   160	
   161	The remainder of this section consists of an implementation in K of the
   162	operations listed above. Users of the `ARRAY` module should not make use
   163	of any of the syntax defined in any of these modules.
   164	
   165	```k
   166	  syntax Array ::= arr(List, Int, KItem)
   167	
   168	  rule makeArray(I::Int, D::KItem) => arr(.List, I, D)
   169	
   170	  rule arr(L::List, _, _       ) [ IDX::Int ] => L[IDX] requires 0 <=Int IDX andBool IDX  <Int size(L)
   171	  rule arr(_      , _, D::KItem) [ _        ] => D      [owise]
   172	
   173	  syntax List ::= ensureOffsetList(List, Int, KItem) [function]
   174	  rule ensureOffsetList(L::List, IDX::Int, D::KItem) => L makeList(IDX +Int 1 -Int size(L), D) requires         IDX >=Int size(L)

   176	
   177	  rule arr(L::List, I::Int, D::KItem) [ IDX::Int <- VAL::KItem ] => arr(ensureOffsetList(L, IDX, D) [ IDX <- VAL ], I, D)
   178	
   179	  rule arr(L::List, I::Int, D::KItem) [ IDX::Int <- undef ] => arr(L, I, D) [ IDX <- D ]

   202	Maps
   203	----
   204	
   205	Provided here is the syntax of an implementation of immutable, associative,
   206	commutative maps from `KItem` to `KItem`. This type is hooked to an
   207	implementation of maps provided by the backend. For more information on
   208	matching on maps and allowable patterns for doing so, refer to K's
   209	[user documentation](USER_MANUAL.md).
   210	
   211	```k
   212	module MAP
   213	  imports private BOOL-SYNTAX
   214	  imports private INT-SYNTAX
   215	  imports private LIST
   216	  imports private SET
   217	
   218	  syntax Map [hook(MAP.Map)]
   219	```
   220	
   221	### Map concatenation
   222	
   223	The `Map` sort represents a generalized associative array. Each key can be
   224	paired with an arbitrary value, and can be used to reference its associated
   225	value. Multiple bindings for the same key are not allowed.
   226	
   227	You can construct a new Map consisting of key/value pairs of two Maps. The
   228	result is `#False` if the maps have keys in common (in particular, this will
   229	yield an exception during concrete execution). This operation is O(N*log(M))
   230	where N is the size of the smaller map, when it appears on the right hand side.
   231	When it appears on the left hand side and all variables are bound, it is
   232	O(N*log(M)) where M is the size of the map it is matching and N is the number
   233	of elements being matched. When it appears on the left hand side containing
   234	variables not bound elsewhere in the term, it is O(N^K) where N is the size of
   235	the map it is matching and K is the number of unbound keys being matched. In
   236	other words, one unbound variable is linear, two is quadratic, three is cubic,
   237	etc.
   238	
   239	```k
   240	  syntax Map ::= Map Map                        [left, function, hook(MAP.concat), symbol(_Map_), assoc, comm, unit(.Map), element(_|->_), index(0), format(%1%n%2)]
   241	```
   242	
   243	### Map unit
   244	
   245	The map with zero elements is represented by `.Map`.
   246	
   247	```k
   248	  syntax Map ::= ".Map"                         [function, total, hook(MAP.unit), symbol(.Map)]
   249	```
   250	
   251	### Map elements
   252	
   253	An element of a `Map` is constructed via the `|->` operator. The key is on the
   254	left and the value is on the right.
   255	
   256	```k
   257	  syntax Map ::= KItem "|->" KItem                      [function, total, hook(MAP.element), symbol(_|->_), injective]
   258	
   259	  syntax priority _|->_ > _Map_ .Map
   260	  syntax non-assoc _|->_
   261	```
   262	
   263	### Map lookup
   264	
   265	You can look up the value associated with the key of a map in O(log(N)) time.
   266	Note that the base of the logarithm is a relatively high number and thus the
   267	time is effectively constant. The value is `#False` if the key is not in the
   268	map (in particular, this will yield an exception during concrete execution).
   269	
   270	```k
   271	  syntax KItem ::= Map "[" KItem "]"                    [function, hook(MAP.lookup), symbol(Map:lookup)]
   272	```
   273	
   274	### Map lookup with default
   275	
   276	You can also look up the value associated with the key of a map using a
   277	total function that assigns a specific default value if the key is not present
   278	in the map. This operation is also O(log(N)), or effectively constant.
   279	
   280	```k
   281	  syntax KItem ::= Map "[" KItem "]" "orDefault" KItem      [function, total, hook(MAP.lookupOrDefault), symbol(Map:lookupOrDefault)]
   282	```
   283	
   284	### Map update
   285	
   286	You can insert a key/value pair into a map in O(log(N)) time, or effectively
   287	constant.
   288	
   289	```k
   290	  syntax Map ::= Map "[" key: KItem "<-" value: KItem "]"           [function, total, symbol(Map:update), hook(MAP.update), prefer]
   291	```
   292	
   293	### Map delete
   294	
   295	You can remove a key/value pair from a map via its key in O(log(N)) time, or
   296	effectively constant.
   297	
   298	```k
   299	  syntax Map ::= Map "[" KItem "<-" "undef" "]"     [function, total, hook(MAP.remove), symbol(_[_<-undef])]
   300	```
   301	
   302	### Map difference
   303	
   304	You can remove the key/value pairs in a map that are present in another map in
   305	O(N*log(M)) time (where M is the size of the first map and N is the size of the
   306	second), or effectively linear. Note that only keys whose value is the same
   307	in both maps are removed. To remove all the keys in one map from another map,
   308	you can say `removeAll(M1, keys(M2))`.
   309	
   310	```k
   311	  syntax Map ::= Map "-Map" Map                 [function, total, hook(MAP.difference)]
   312	```
   313	
   314	### Multiple map update
   315	
   316	You can update a map by adding all the key/value pairs in the second map in
   317	O(N*log(M)) time (where M is the size of the first map and N is the size of the
   318	second map), or effectively linear. If any keys are present in both maps, the
   319	value from the second map overwrites the value in the first. This function is
   320	total, which is distinct from map concatenation, a partial function only
   321	defined on maps with disjoint keys.
   322	
   323	```k
   324	  syntax Map ::= updateMap(Map, Map)            [function, total, hook(MAP.updateAll)]
   325	```
   326	
   327	### Multiple map removal
   328	
   329	You can remove a `Set` of keys from a map in O(N*log(M)) time (where M is the
   330	size of the `Map` and `N` is the size of the `Set`), or effectively linear.
   331	
   332	```k
   333	  syntax Map ::= removeAll(Map, Set)            [function, total, hook(MAP.removeAll)]
   334	```
   335	
   336	### Map keys (as `Set`)
   337	
   338	You can get a `Set` of all the keys in a Map in O(N) time.
   339	
   340	```k
   341	  syntax Set ::= keys(Map)                      [function, total, hook(MAP.keys)]
   342	```
   343	
   344	### Map keys (as `List`)
   345	
   346	You can get a `List` of all the keys in a Map in O(N) time.
   347	
   348	```k
   349	  syntax List ::= "keys_list" "(" Map ")"       [function, hook(MAP.keys_list)]
   350	```
   351	
   352	### Map key membership
   353	
   354	You can check whether a key is present in a map in O(1) time.
   355	
   356	```k
   357	  syntax Bool ::= KItem "in_keys" "(" Map ")"       [function, total, hook(MAP.in_keys)]
   358	```
   359	
   360	### Map values (as `List`)
   361	
   362	You can get a `List` of all the values in a map in O(N) time.
   363	
   364	```k
   365	  syntax List ::= values(Map)                   [function, hook(MAP.values)]
   366	```
   367	
   368	### Map size
   369	
   370	You can get the number of key/value pairs in a map in O(1) time.
   371	
   372	```k
   373	  syntax Int ::= size(Map)                      [function, total, hook(MAP.size), symbol(sizeMap)]
   374	```
   375	
   376	### Map inclusion
   377	
   378	You can determine whether a `Map` is a strict subset of another `Map` in O(N)
   379	time (where N is the size of the first map). Only keys that are bound to the
   380	same value are considered equal.
   381	
   382	```k
   383	  syntax Bool ::= Map "<=Map" Map               [function, total, hook(MAP.inclusion)]
   384	```
   385	
   386	### Map choice
   387	
   388	You can get an arbitrarily chosen key of a `Map` in O(1) time. The same key
   389	will always be returned for the same map, but no guarantee is given that two
   390	different maps will return the same element, even if they are similar.
   391	
   392	```k
   393	  syntax KItem ::= choice(Map)                      [function, hook(MAP.choice), symbol(Map:choice)]
   394	```
   395	
   396	### Implementation of Maps
   397	
   398	The remainder of this section contains lemmas used by the Java and Haskell
   399	backend to simplify expressions of sort `Map`. They do not affect the semantics
   400	of maps, merely describing additional rules that the backend can use to
   401	simplify terms.
   402	
   403	```k
   404	endmodule
   405	
   406	module MAP-KORE-SYMBOLIC [symbolic,haskell]
   407	  imports MAP
   408	  imports private K-EQUAL
   409	  imports private BOOL
   410	
   411	  rule #Ceil(@M:Map [@K:KItem]) => {(@K in_keys(@M)) #Equals true} #And #Ceil(@M) #And #Ceil(@K) [simplification]
   412	
   413	  // Symbolic update
   414	
   415	  // Adding the definedness condition `notBool (K in_keys(M))` in the ensures clause of the following rule would be redundant
   416	  // because K also appears in the rhs, preserving the case when it's #Bottom.
   417	  rule (K |-> _ M:Map) [ K <- V ] => (K |-> V M) [simplification]
   418	  rule M:Map [ K <- V ] => (K |-> V M) requires notBool (K in_keys(M)) [simplification]
   419	  rule M:Map [ K <- _ ] [ K <- V ] => M [ K <- V ] [simplification]
   420	  // Adding the definedness condition `notBool (K1 in_keys(M))` in the ensures clause of the following rule would be redundant
   421	  // because K1 also appears in the rhs, preserving the case when it's #Bottom.
   422	  rule (K1 |-> V1 M:Map) [ K2 <- V2 ] => (K1 |-> V1 (M [ K2 <- V2 ])) requires K1 =/=K K2 [simplification]
   423	
   424	  // Symbolic remove
   425	  rule (K |-> _ M:Map) [ K <- undef ] => M ensures notBool (K in_keys(M)) [simplification]
   426	  rule M:Map [ K <- undef ] => M requires notBool (K in_keys(M)) [simplification]
   427	  // Adding the definedness condition `notBool (K1 in_keys(M))` in the ensures clause of the following rule would be redundant
   428	  // because K1 also appears in the rhs, preserving the case when it's #Bottom.
   429	  rule (K1 |-> V1 M:Map) [ K2 <- undef ] => (K1 |-> V1 (M [ K2 <- undef ])) requires K1 =/=K K2 [simplification]
   430	
   431	  // Symbolic lookup
   432	  rule (K  |->  V M:Map) [ K ]  => V ensures notBool (K in_keys(M)) [simplification]
   433	  rule (K1 |-> _V M:Map) [ K2 ] => M [K2] requires K1 =/=K K2 ensures notBool (K1 in_keys(M)) [simplification]
   434	  rule (_MAP:Map [ K  <-  V1 ]) [ K ]  => V1 [simplification]
   435	  rule ( MAP:Map [ K1 <- _V1 ]) [ K2 ] => MAP [ K2 ] requires K1 =/=K K2 [simplification]
   436	
   437	  rule (K  |->  V M:Map) [  K ] orDefault _ => V ensures notBool (K in_keys(M)) [simplification]
   438	  rule (K1 |-> _V M:Map) [ K2 ] orDefault D => M [K2] orDefault D requires K1 =/=K K2 ensures notBool (K1 in_keys(M)) [simplification]
   439	  rule (_MAP:Map [ K  <-  V1 ]) [ K ] orDefault _ => V1 [simplification]
   440	  rule ( MAP:Map [ K1 <- _V1 ]) [ K2 ] orDefault D => MAP [ K2 ] orDefault D requires K1 =/=K K2 [simplification]
   441	  rule .Map [ _ ] orDefault D => D [simplification]
   442	
   443	  // Symbolic in_keys
   444	  rule K in_keys(_M [ K <- undef ]) => false [simplification]
   445	  rule K in_keys(_M [ K <- _ ]) => true [simplification]
   446	  rule K1 in_keys(M [ K2 <- _ ]) => true requires K1 ==K K2 orBool K1 in_keys(M) [simplification]
   447	  rule K1 in_keys(M [ K2 <- _ ]) => K1 in_keys(M) requires K1 =/=K K2 [simplification]
   448	
   449	  rule {false #Equals @Key in_keys(.Map)} => #Ceil(@Key) [simplification]
   450	  rule {@Key in_keys(.Map) #Equals false} => #Ceil(@Key) [simplification]
   451	  rule {false #Equals @Key in_keys(Key' |-> Val @M)} => #Ceil(@Key) #And #Ceil(Key' |-> Val @M) #And #Not({@Key #Equals Key'}) #And {false #Equals @Key in_keys(@M)} [simplification]
   452	  rule {@Key in_keys(Key' |-> Val @M) #Equals false} => #Ceil(@Key) #And #Ceil(Key' |-> Val @M) #And #Not({@Key #Equals Key'}) #And {@Key in_keys(@M) #Equals false} [simplification]
   453	
   454	/*
   455	// The rule below is automatically generated by the frontend for every sort
   456	// hooked to MAP.Map. It is left here to serve as documentation.
   457	
   458	  rule #Ceil(@M:Map (@K:KItem |-> @V:KItem)) => {(@K in_keys(@M)) #Equals false} #And #Ceil(@M) #And #Ceil(@K) #And #Ceil(@V)
   459	    [simplification]
   460	*/
   461	endmodule
   462	
   463	module MAP-SYMBOLIC
   464	  imports MAP-KORE-SYMBOLIC
   465	endmodule
   466	```

   468	Range Maps
   469	----
   470	
   471	Provided here is the syntax of an implementation of immutable, associative,
   472	commutative range maps from `Int` to `KItem`. This type is hooked to an
   473	implementation of range maps provided by the LLVM backend.
   474	Currently, this type is not supported by other backends.
   475	Although the underlying range map data structure supports any key sort, the
   476	current implementation by the backend only supports `Int` keys due to
   477	limitations of the underlying ordering function.
   478	
   479	```k
   480	module RANGEMAP
   481	  imports private BOOL-SYNTAX
   482	  imports private INT-SYNTAX
   483	  imports private LIST
   484	  imports private SET
   485	
   486	```
   487	
   488	### Range, bounded inclusively below and exclusively above.
   489	
   490	```k
   491	  syntax Range ::= "[" KItem "," KItem ")"    [symbol(RangeMap:Range)]
   492	
   493	  syntax RangeMap [hook(RANGEMAP.RangeMap)]
   494	```
   495	
   496	### Range map concatenation
   497	
   498	The `RangeMap` sort represents a map whose keys are stored as ranges, bounded
   499	inclusively below and exclusively above. Contiguous or overlapping ranges that
   500	map to the same value are merged into a single range.
   501	
   502	You can construct a new `RangeMap` consisting of range/value pairs of two
   503	RangeMaps. If the RangeMaps have overlapping ranges an exception will be
   504	thrown during concrete execution. This operation is O(N*log(M)) (where N is
   505	the size of the smaller map and M is the size of the larger map).
   506	
   507	```k
   508	  syntax RangeMap ::= RangeMap RangeMap                        [left, function, hook(RANGEMAP.concat), symbol(_RangeMap_), assoc, comm, unit(.RangeMap), element(_r|->_), index(0), format(%1%n%2)]
   509	```
   510	
   511	### Range map unit
   512	
   513	The `RangeMap` with zero elements is represented by `.RangeMap`.
   514	
   515	```k
   516	  syntax RangeMap ::= ".RangeMap"                         [function, total, hook(RANGEMAP.unit), symbol(.RangeMap)]
   517	```
   518	
   519	### Range map elements
   520	
   521	An element of a `RangeMap` is constructed via the `r|->` operator. The range
   522	of keys is on the left, and the value is on the right.
   523	
   524	```k
   525	  syntax RangeMap ::= Range "r|->" KItem                      [function, hook(RANGEMAP.elementRng), symbol(_r|->_), injective]
   526	
   527	  syntax priority _r|->_ > _RangeMap_ .RangeMap
   528	  syntax non-assoc _r|->_
   529	```
   530	
   531	### Range map lookup
   532	
   533	You can look up the value associated with a key of a `RangeMap` in O(log(N))
   534	time (where N is the size of the `RangeMap`). This will yield an exception
   535	during concrete execution if the key is not in the range map.
   536	
   537	```k
   538	  syntax KItem ::= RangeMap "[" KItem "]"                    [function, hook(RANGEMAP.lookup), symbol(RangeMap:lookup)]
   539	```
   540	
   541	### Range map lookup with default
   542	
   543	You can also look up the value associated with a key of a `RangeMap` using a
   544	total function that assigns a specific default value if the key is not present
   545	in the `RangeMap`. This operation is also O(log(N)) (where N is the size of
   546	the range map).
   547	
   548	```k
   549	  syntax KItem ::= RangeMap "[" KItem "]" "orDefault" KItem      [function, total, hook(RANGEMAP.lookupOrDefault), symbol(RangeMap:lookupOrDefault)]
   550	```
   551	
   552	### Range map lookup for range of key
   553	
   554	You can look up for the range that a key of a `RangeMap` is stored in in
   555	O(log(N)) time (where N is the size of the `RangeMap`). This will yield an
   556	exception during concrete execution if the key is not in the range map.
   557	
   558	```k
   559	  syntax Range ::= "find_range" "(" RangeMap "," KItem ")"                    [function, hook(RANGEMAP.find_range), symbol(RangeMap:find_range)]
   560	```
   561	
   562	### Range map update
   563	
   564	You can insert a range/value pair into a `RangeMap` in O(log(N)) time (where N
   565	is the size of the `RangeMap`). Any ranges adjacent to or overlapping with the
   566	range to be inserted will be updated accordingly.
   567	
   568	```k
   569	  syntax RangeMap ::= RangeMap "[" keyRange: Range "<-" value: KItem "]"           [function, symbol(RangeMap:update), hook(RANGEMAP.updateRng), prefer]
   570	```
   571	
   572	### Range map delete
   573	
   574	You can remove a range/value pair from a `RangeMap` in O(log(N)) time (where N
   575	is the size of the `RangeMap`). If all or any part of the range is present in
   576	the range map, it will be removed.
   577	
   578	```k
   579	  syntax RangeMap ::= RangeMap "[" Range "<-" "undef" "]"     [function, hook(RANGEMAP.removeRng), symbol(_r[_<-undef])]
   580	```
   581	
   582	### Range map difference
   583	
   584	You can remove the range/value pairs in a `RangeMap` that are also present in
   585	another `RangeMap` in O(max{M,N}*log(M)) time (where M is the size of the
   586	first `RangeMap` and N is the size of the second `RangeMap`). Note that only
   587	the parts of overlapping ranges whose value is the same in both range maps
   588	will be removed.
   589	
   590	```k
   591	  syntax RangeMap ::= RangeMap "-RangeMap" RangeMap                 [function, total, hook(RANGEMAP.difference)]
   592	```
   593	
   594	### Multiple range map update
   595	
   596	You can update a `RangeMap` by adding all the range/value pairs in the second
   597	`RangeMap` in O(N*log(M+N)) time (where M is the size of the first `RangeMap`
   598	and N is the size of the second `RangeMap`). If any ranges are overlapping,
   599	the value from the second range map overwrites the value in the first for the
   600	parts where ranges are overlapping. This function is total, which is distinct
   601	from range map concatenation, a partial function only defined on range maps
   602	with non overlapping ranges.
   603	
   604	```k
   605	  syntax RangeMap ::= updateRangeMap(RangeMap, RangeMap)            [function, total, hook(RANGEMAP.updateAll)]
   606	```
   607	
   608	### Multiple range map removal
   609	
   610	You can remove a `Set` of ranges from a `RangeMap` in O(N*log(M)) time (where
   611	M is the size of the `RangeMap` and N is the size of the `Set`). For every
   612	range in the set, all or any part of it that is present in the range map will
   613	be removed.
   614	
   615	```k
   616	  syntax RangeMap ::= removeAll(RangeMap, Set)            [function, hook(RANGEMAP.removeAll)]
   617	```
   618	
   619	### Range map keys (as `Set`)
   620	
   621	You can get a `Set` of all the ranges in a `RangeMap` in O(N) time (where N
   622	is the size of the `RangeMap`).
   623	
   624	```k
   625	  syntax Set ::= keys(RangeMap)                      [function, total, hook(RANGEMAP.keys)]
   626	```
   627	
   628	### Range map keys (as `List`)
   629	
   630	You can get a `List` of all the ranges in a `RangeMap` in O(N) time (where N
   631	is the size of the `RangeMap`).
   632	
   633	```k
   634	  syntax List ::= "keys_list" "(" RangeMap ")"       [function, hook(RANGEMAP.keys_list)]
   635	```
   636	
   637	### Range map key membership
   638	
   639	You can check whether a key is present in a `RangeMap` in O(log(N)) time (where
   640	N is the size of the `RangeMap`).
   641	
   642	```k
   643	  syntax Bool ::= KItem "in_keys" "(" RangeMap ")"       [function, total, hook(RANGEMAP.in_keys)]
   644	```
   645	
   646	### Range map values (as `List`)
   647	
   648	You can get a `List` of all values in a `RangeMap` in O(N) time (where N is the
   649	size of the `RangeMap`).
   650	
   651	```k
   652	  syntax List ::= values(RangeMap)                   [function, hook(RANGEMAP.values)]
   653	```
   654	
   655	### Range map size
   656	
   657	You can get the number of range/value pairs in a `RangeMap` in O(1) time.
   658	
   659	```k
   660	  syntax Int ::= size(RangeMap)                      [function, total, hook(RANGEMAP.size), symbol(sizeRangeMap)]
   661	```
   662	
   663	### Range map inclusion
   664	
   665	You can determine whether a `RangeMap` is a strict subset of another `RangeMap`
   666	in O(M+N) time (where M is the size of the first `RangeMap` and N is the size
   667	of the second `RangeMap`). Only keys within equal or overlapping ranges that
   668	are bound to the same value are considered equal.
   669	
   670	```k
   671	  syntax Bool ::= RangeMap "<=RangeMap" RangeMap               [function, total, hook(RANGEMAP.inclusion)]
   672	```
   673	
   674	### Range map choice
   675	
   676	You can get an arbitrarily chosen key of a `RangeMap` in O(1) time. The same
   677	key will always be returned for the same range map, but no guarantee is given
   678	that two different range maps will return the same element, even if they are
   679	similar.
   680	
   681	```k
   682	  syntax KItem ::= choice(RangeMap)                      [function, hook(RANGEMAP.choice), symbol(RangeMap:choice)]
   683	endmodule
   684	```

   686	Sets
   687	----
   688	
   689	Provided here is the syntax of an implementation of immutable, associative,
   690	commutative sets of `KItem`. This type is hooked to an implementation of sets
   691	provided by the backend. For more information on matching on sets and allowable
   692	patterns for doing so, refer to K's
   693	[user documentation](USER_MANUAL.md).
   694	
   695	```k
   696	module SET
   697	  imports private INT-SYNTAX
   698	  imports private BASIC-K
   699	
   700	  syntax Set [hook(SET.Set)]
   701	```
   702	
   703	### Set concatenation
   704	
   705	The `Set` sort represents a mathematical set (A collection of unique items).
   706	The sets are nilpotent, i.e., the concatenation of two sets containing elements
   707	in common is `#False` (note however, this may be silently allowed during
   708	concrete execution). If you intend to add an element to a set that might
   709	already be present in the set, use the `|Set` operator instead.
   710	
   711	The concatenation operator is O(N*log(M)) where N is the size of the smaller
   712	set, when it appears on the right hand side. When it appears on the left hand
   713	side and all variables are bound, it is O(N*log(M)) where M is the size of the
   714	set it is matching and N is the number of elements being matched. When it
   715	appears on the left hand side containing variables not bound elsewhere in the
   716	term, it is O(N^K) where N is the size of the set it is matching and K is the
   717	number of unbound keys being mached. In other words, one unbound variable is
   718	linear, two is quadratic, three is cubic, etc.
   719	
   720	```k
   721	  syntax Set ::= Set Set                  [left, function, hook(SET.concat), symbol(_Set_), assoc, comm, unit(.Set), idem, element(SetItem), format(%1%n%2)]
   722	```
   723	
   724	### Set unit
   725	
   726	The set with zero elements is represented by `.Set`.
   727	
   728	```k
   729	  syntax Set ::= ".Set"                   [function, total, hook(SET.unit), symbol(.Set)]
   730	```
   731	
   732	### Set elements
   733	
   734	An element of a `Set` is constructed via the `SetItem` operator.
   735	
   736	```k
   737	  syntax Set ::= SetItem(KItem)               [function, total, hook(SET.element), symbol(SetItem), injective]
   738	```
   739	
   740	### Set union
   741	
   742	You can compute the union of two sets in O(N*log(M)) time (Where N is the size
   743	of the smaller set). Note that the base of the logarithm is a relatively high
   744	number and thus the time is effectively linear. The union consists of all the
   745	elements present in either set.
   746	
   747	```k
   748	  syntax Set ::= Set "|Set" Set              [left, function, total, hook(SET.union), comm]
   749	  rule S1:Set |Set S2:Set => S1 (S2 -Set S1) [concrete]
   750	```
   751	
   752	### Set intersection
   753	
   754	You can compute the intersection of two sets in O(N*log(M)) time (where N
   755	is the size of the smaller set), or effectively linear. The intersection
   756	consists of all the elements present in both sets.
   757	
   758	```k
   759	  syntax Set ::= intersectSet(Set, Set)   [function, total, hook(SET.intersection), comm]
   760	```
   761	
   762	### Set complement
   763	
   764	You can compute the relative complement of two sets in O(N*log(M)) time (where
   765	N is the size of the second set), or effectively linear. This is the set of
   766	elements in the first set that are not present in the second set.
   767	
   768	```k
   769	  syntax Set ::= Set "-Set" Set           [function, total, hook(SET.difference), symbol(Set:difference)]
   770	```
   771	
   772	### Set membership
   773	
   774	You can compute whether an element is a member of a set in O(1) time.
   775	
   776	```k
   777	  syntax Bool ::= KItem "in" Set              [function, total, hook(SET.in), symbol(Set:in)]
   778	```
   779	
   780	### Set inclusion
   781	
   782	You can determine whether a `Set` is a strict subset of another `Set` in O(N)
   783	time (where N is the size of the first set).
   784	
   785	```k
   786	  syntax Bool ::= Set "<=Set" Set         [function, total, hook(SET.inclusion)]
   787	```
   788	
   789	### Set size
   790	
   791	You can get the number of elements (the cardinality) of a set in O(1) time.
   792	
   793	```k
   794	  syntax Int ::= size(Set)                [function, total, hook(SET.size)]
   795	```
   796	
   797	### Set choice
   798	
   799	You can get an arbitrarily chosen element of a `Set` in O(1) time. The same
   800	element will always be returned for the same set, but no guarantee is given
   801	that two different sets will return the same element, even if they are similar.
   802	
   803	```k
   804	  syntax KItem ::= choice(Set)                [function, hook(SET.choice), symbol(Set:choice)]
   805	```
   806	
   807	```k
   808	endmodule
   809	```

   816	```k
   817	module SET-KORE-SYMBOLIC [symbolic,haskell]

   820	  imports private BOOL

   850	
   851	
   852

   861	  //                            ensures notBool (X in S) [simplification, comm]
   862

   899	Lists
   900	-----
   901	
   902	Provided here is the syntax of an implementation of immutable, associative
   903	lists of `KItem`. This type is hooked to an implementation of lists provided
   904	by the backend. For more information on matching on lists and allowable
   905	patterns for doing so, refer to K's
   906	[user documentation](USER_MANUAL.md).
   907	
   908	```k
   909	module LIST
   910	  imports private INT-SYNTAX
   911	  imports private MINT-SYNTAX
   912	  imports private BASIC-K
   913	
   914	  syntax List [hook(LIST.List)]
   915	```
   916	
   917	### List concatenation
   918	
   919	The `List` sort is an ordered collection that may contain duplicate elements.
   920	They are backed by relaxed radix balanced trees, which means that they support
   921	efficiently adding elements to both sides of the list, concatenating two lists,
   922	indexing, and updating elements.
   923	
   924	The concatenation operator is O(log(N)) (where N is the size of the longer
   925	list) when it appears on the right hand side. When it appears on the left hand
   926	side, it is O(N), where N is the number of elements matched on the front and
   927	back of the list.
   928	
   929	```k
   930	  syntax List ::= List List               [left, function, total, hook(LIST.concat), symbol(_List_), smtlib(smt_seq_concat), assoc, unit(.List), element(ListItem), update(List:set), format(%1%n%2)]
   931	```
   932	
   933	### List unit
   934	
   935	The list with zero elements is represented by `.List`.
   936	
   937	```k
   938	  syntax List ::= ".List"                 [function, total, hook(LIST.unit), symbol(.List), smtlib(smt_seq_nil)]
   939	```
   940	
   941	### List elements
   942	
   943	An element of a `List` is constucted via the `ListItem` operator.
   944	
   945	```k
   946	  syntax List ::= ListItem(KItem)             [function, total, hook(LIST.element), symbol(ListItem), smtlib(smt_seq_elem)]
   947	```
   948	
   949	### List prepend
   950	
   951	An element can be added to the front of a `List` using the `pushList` operator.
   952	
   953	```k
   954	  syntax List ::= pushList(KItem, List)       [function, total, hook(LIST.push), symbol(pushList)]
   955	  rule pushList(K::KItem, L1::List) => ListItem(K) L1
   956	```
   957	
   958	### List indexing
   959	
   960	You can get an element of a list by its integer offset in O(log(N)) time, or
   961	effectively constant. Positive `Int` indices are 0-indexed from the beginning of the
   962	list, and negative indices are -1-indexed from the end of the list. In other
   963	words, 0 is the first element and -1 is the last element. The indice can also be
   964	`MInt`, which is interprested as an unsigned integer, and therefore, don't support
   965	negative indices feature. Currently, only 64-bit and 256-bit `MInt` types are supported.
   966	
   967	```k
   968	  syntax KItem ::= List "[" Int "]"           [function, hook(LIST.get), symbol(List:get)]
   969	  syntax {Width} KItem ::= List "[" MInt{Width} "]" [function, hook(LIST.getMInt), symbol(List:getMInt)]
   970	```
   971	
   972	### List update
   973	
   974	You can create a new `List` with a new value at a particular index in
   975	O(log(N)) time, or effectively constant. The index can be either as an `Int` or as an `MInt`. Currently, only 64-bit `MInt` type is supported.
   976	
   977	```k
   978	  syntax List ::= List "[" index: Int "<-" value: KItem "]" [function, hook(LIST.update), symbol(List:set)]
   979	  syntax {Width} List ::= List "[" index: MInt{Width} "<-" value: KItem "]" [function, hook(LIST.updateMInt), symbol(List:setMInt)]
   980	```
   981	
   982	### List of identical elements
   983	
   984	You can create a list with `length` elements, each containing `value`, in O(N)
   985	time.
   986	
   987	```k
   988	  syntax List ::= makeList(length: Int, value: KItem) [function, hook(LIST.make)]
   989	```
   990	
   991	### Multiple list update
   992	
   993	You can create a new `List` which is equal to `dest` except the `N` elements
   994	starting at `index` are replaced with the contents of `src` in O(N*log(K)) time
   995	(where `K` is the size of `dest`and `N` is the size of `src`), or effectively linear. Having `index + N > K` yields an exception.
   996	
   997	```k
   998	  syntax List ::= updateList(dest: List, index: Int, src: List) [function, hook(LIST.updateAll)]
   999	```
  1000	
  1001	### List fill
  1002	
  1003	You can create a new `List` where the `length` elements starting at `index`
  1004	are replaced with `value`, in O(length*log(N)) time, or effectively linear.
  1005	
  1006	```k
  1007	  syntax List ::= fillList(List, index: Int, length: Int, value: KItem) [function, hook(LIST.fill)]
  1008	```
  1009	
  1010	### List slicing
  1011	
  1012	You can compute a new `List` by removing `fromFront` elements from the front
  1013	of the list and `fromBack` elements from the back of the list in
  1014	O((fromFront+fromBack)*log(N)) time, or effectively linear.
  1015	
  1016	```k
  1017	  syntax List ::= range(List, fromFront: Int, fromBack: Int)   [function, hook(LIST.range), symbol(List:range)]
  1018	```
  1019	
  1020	### List membership
  1021	
  1022	You can compute whether an element is in a list in O(N) time. For repeated
  1023	comparisons, it is much better to first convert to a set using `List2Set`.
  1024	
  1025	```k
  1026	  syntax Bool ::= KItem "in" List             [function, total, hook(LIST.in), symbol(_inList_)]
  1027	```
  1028	
  1029	### List size
  1030	
  1031	You can get the number of elements of a list in O(1) time. The output
  1032	size can be either as an `Int` or as an `MInt`. Currently, only 64-bit
  1033	and 256-bit `MInt` types are supported. When using `MInt`, the size is
  1034	interpreted as an unsigned integer, and the size of the list must match
  1035	the bounds of this `MInt` type, that is the size can't be larger than
  1036	`2^64 - 1` for `MInt{64}` and `2^256 - 1` for `MInt{256}`.
  1037	
  1038	```k
  1039	  syntax Int ::= size(List)               [function, total, hook(LIST.size), symbol(sizeList), smtlib(smt_seq_len)]
  1040	  syntax {Width} MInt{Width} ::= size(List) [function, hook(LIST.sizeMInt), symbol(sizeMInt)]
  1041	```

  1043	```k
  1044	endmodule

  1047	Collection Conversions
  1048	----------------------
  1049	
  1050	It is possible to convert from a `List` to a `Set` or from a `Set` to a list.
  1051	Converting from a `List` to a `Set` and back will not provide the same list;
  1052	duplicates will have been removed and the list may be reordered. Converting
  1053	from a `Set` to a `List` and back will generate the same set.
  1054	
  1055	Note that because sets are unordered and lists are ordered, converting from a
  1056	Set to a List will generate some arbitrary ordering of elements, which may
  1057	be different from the natural ordering you might assume, or may not. Two
  1058	equal sets are guaranteed to generate the same ordering, but no guarantee is
  1059	otherwise provided about what the ordering will be. In particular, adding an
  1060	element to a set may completely reorder the elements already in the set, when
  1061	it is converted to a list.
  1062	
  1063	```k
  1064	module COLLECTIONS
  1065	  imports LIST
  1066	  imports SET
  1067	  imports MAP
  1068	
  1069	  syntax List ::= Set2List(Set) [function, total, hook(SET.set2list)]
  1070	  syntax Set ::= List2Set(List) [function, total, hook(SET.list2set)]
  1071	
  1072	endmodule
  1073	```

  1102	### Basic boolean arithmetic
  1103	
  1104	You can:
  1105	
  1106	* Negate a boolean value.
  1107	* AND two boolean values.
  1108	* XOR two boolean values.
  1109	* OR two boolean values.
  1110	* IMPLIES two boolean values (i.e., `P impliesBool Q` is the same as
  1111	  `notBool P orBool Q`)
  1112	* Check equality of two boolean values.
  1113	* Check inequality of two boolean values.
  1114	
  1115	Note that only `andThenBool` and `orElseBool` are short-circuiting. `andBool`
  1116	and `orBool` may be short-circuited in concrete backends, but in symbolic
  1117	backends, both arguments will be evaluated.
  1118	
  1119	```k
  1120	  syntax Bool ::= "notBool" Bool          [function, total, symbol(notBool_), smt-hook(not), group(boolOperation), hook(BOOL.not)]
  1121	                > Bool "andBool" Bool     [function, total, symbol(_andBool_), left, smt-hook(and), group(boolOperation), hook(BOOL.and)]
  1122	                | Bool "andThenBool" Bool [function, total, symbol(_andThenBool_), left, smt-hook(and), group(boolOperation), hook(BOOL.andThen)]
  1123	                | Bool "xorBool" Bool     [function, total, symbol(_xorBool_), left, smt-hook(xor), group(boolOperation), hook(BOOL.xor)]
  1124	                | Bool "orBool" Bool      [function, total, symbol(_orBool_), left, smt-hook(or), group(boolOperation), hook(BOOL.or)]
  1125	                | Bool "orElseBool" Bool  [function, total, symbol(_orElseBool_), left, smt-hook(or), group(boolOperation), hook(BOOL.orElse)]
  1126	                | Bool "impliesBool" Bool [function, total, symbol(_impliesBool_), left, smt-hook(=>), group(boolOperation), hook(BOOL.implies)]
  1127	                > left:
  1128	                  Bool "==Bool" Bool      [function, total, symbol(_==Bool_), left, comm, smt-hook(=), hook(BOOL.eq)]
  1129	                | Bool "=/=Bool" Bool     [function, total, symbol(_=/=Bool_), left, comm, smt-hook(distinct), hook(BOOL.ne)]
  1130	```

  1132	### Implementation of Booleans
  1133	
  1134	The remainder of this section consists of an implementation in K of the
  1135	operations listed above.
  1136	
  1137	```k
  1138	  rule notBool true => false
  1139	  rule notBool false => true
  1140	
  1141	  rule true andBool B:Bool => B:Bool
  1142	  rule B:Bool andBool true => B:Bool [simplification]
  1143	  rule false andBool _:Bool => false
  1144	  rule _:Bool andBool false => false [simplification]
  1145	
  1146	  rule true andThenBool K::Bool => K
  1147	  rule K::Bool andThenBool true => K [simplification]
  1148	  rule false andThenBool _ => false
  1149	  rule _ andThenBool false => false  [simplification]
  1150	
  1151	  rule false xorBool B:Bool => B:Bool
  1152	  rule B:Bool xorBool false => B:Bool [simplification]
  1153	  rule B:Bool xorBool B:Bool => false
  1154	
  1155	  rule true orBool _:Bool => true
  1156	  rule _:Bool orBool true => true [simplification]
  1157	  rule false orBool B:Bool => B
  1158	  rule B:Bool orBool false => B   [simplification]
  1159	
  1160	  rule true orElseBool _ => true
  1161	  rule _ orElseBool true => true     [simplification]
  1162	  rule false orElseBool K::Bool => K
  1163	  rule K::Bool orElseBool false => K [simplification]
  1164	
  1165	  rule true impliesBool B:Bool => B
  1166	  rule false impliesBool _:Bool => true
  1167	  rule _:Bool impliesBool true => true       [simplification]
  1168	  rule B:Bool impliesBool false => notBool B [simplification]
  1169	
  1170	  rule B1:Bool =/=Bool B2:Bool => notBool (B1 ==Bool B2)
  1171	endmodule
  1172	
  1173	module BOOL-KORE [symbolic]
  1174	  imports BOOL-COMMON
  1175	
  1176	  rule {true #Equals notBool @B} => {false #Equals @B} [simplification]
  1177	  rule {notBool @B #Equals true} => {@B #Equals false} [simplification]
  1178	  rule {false #Equals notBool @B} => {true #Equals @B} [simplification]
  1179	  rule {notBool @B #Equals false} => {@B #Equals true} [simplification]
  1180	
  1181	  rule {true #Equals @B1 andBool @B2} => {true #Equals @B1} #And {true #Equals @B2} [simplification]
  1182	  rule {@B1 andBool @B2 #Equals true} => {@B1 #Equals true} #And {@B2 #Equals true} [simplification]
  1183	  rule {false #Equals @B1 orBool @B2} => {false #Equals @B1} #And {false #Equals @B2} [simplification]
  1184	  rule {@B1 orBool @B2 #Equals false} => {@B1 #Equals false} #And {@B2 #Equals false} [simplification]
  1185	endmodule
  1186	
  1187	module BOOL
  1188	  imports BOOL-COMMON
  1189	  imports BOOL-KORE
  1190	endmodule

  1222	
  1223	### Integer arithmetic
  1224	
  1225	You can:
  1226	
  1227	* Compute the bitwise complement `~Int` of an integer value in twos-complement.
  1228	* Compute the exponentiation `^Int` of two integers.
  1229	* Compute the exponentiation of two integers modulo another integer (`^%Int`).
  1230	  `A ^%Int B C` is equal in value to `(A ^Int B) %Int C`, but has a better
  1231	  asymptotic complexity.
  1232	* Compute the product `*Int` of two integers.
  1233	* Compute the quotient `/Int` or modulus `%Int` of two integers using
  1234	  t-division, which rounds towards zero. Division by zero is `#False`.
  1235	* Compute the quotient `divInt` or modulus `modInt` of two integers using
  1236	  Euclidean division, in which the remainder is always non-negative. Division
  1237	  by zero is `#False`.
  1238	* Compute the sum `+Int` or difference `-Int` of two integers.
  1239	* Compute the arithmetic right shift `>>Int` of two integers. Shifting by a
  1240	  negative quantity is `#False`.
  1241	* Compute the left shift of two integers. Shifting by a negative quantity is
  1242	  `#False`.
  1243	* Compute the bitwise and of two integers in twos-complement.
  1244	* Compute the bitwise xor of two integers in twos-complement.
  1245	* Compute the bitwise inclusive-or of two integers in twos-complement.
  1246	
  1247	```k
  1248	  syntax Int ::= "~Int" Int                     [function, symbol(~Int_), total, hook(INT.not), smtlib(notInt)]
  1249	               > left:
  1250	                 Int "^Int" Int                 [function, symbol(_^Int_), left, smt-hook(^), hook(INT.pow)]
  1251	               | Int "^%Int" Int Int            [function, symbol(_^%Int__), left, smt-hook((mod (^ #1 #2) #3)), hook(INT.powmod)]
  1252	               > left:
  1253	                 Int "*Int" Int                 [function, total, symbol(_*Int_), left, comm, smt-hook(*), hook(INT.mul)]
  1254	               /* FIXME: translate /Int and %Int into smtlib */
  1255	               /* /Int and %Int implement t-division, which rounds towards 0. SMT hooks need to convert from Euclidian division operations */
  1256	               | Int "/Int" Int                 [function, symbol(_/Int_), left,
  1257	                                                 smt-hook((ite (or (= 0 (mod #1 #2)) (>= #1 0)) (div #1 #2) (ite (> #2 0) (+ (div #1 #2) 1) (- (div #1 #2) 1)))),
  1258	                                                 hook(INT.tdiv)]
  1259	               | Int "%Int" Int                 [function, symbol(_%Int_), left,
  1260	                                                 smt-hook((ite (or (= 0 (mod #1 #2)) (>= #1 0)) (mod #1 #2) (ite (> #2 0) (- (mod #1 #2) #2) (+ (mod #1 #2) #2)))),
  1261	                                                 hook(INT.tmod)]
  1262	               /* divInt and modInt implement e-division according to the Euclidean division theorem, therefore the remainder is always positive */
  1263	               | Int "divInt" Int               [function, symbol(_divInt_), left, smt-hook(div), hook(INT.ediv)]
  1264	               | Int "modInt" Int               [function, symbol(_modInt_), left, smt-hook(mod), hook(INT.emod)]
  1265	               > left:
  1266	                 Int "+Int" Int                 [function, total, symbol(_+Int_), left, comm, smt-hook(+), hook(INT.add)]
  1267	               | Int "-Int" Int                 [function, total, symbol(_-Int_), left, smt-hook(-), hook(INT.sub)]
  1268	               > left:
  1269	                 Int ">>Int" Int                [function, symbol(_>>Int_), left, hook(INT.shr), smtlib(shrInt)]
  1270	               | Int "<<Int" Int                [function, symbol(_<<Int_), left, hook(INT.shl), smtlib(shlInt)]
  1271	               > left:
  1272	                 Int "&Int" Int                 [function, total, symbol(_&Int_), left, comm, hook(INT.and), smtlib(andInt)]
  1273	               > left:
  1274	                 Int "xorInt" Int               [function, total, symbol(_xorInt_), left, comm, hook(INT.xor), smtlib(xorInt)]
  1275	               > left:
  1276	                 Int "|Int" Int                 [function, total, symbol(_|Int_), left, comm, hook(INT.or), smtlib(orInt)]
  1277	```

  1357	
  1358	The remainder of this section consists of an implementation in K of some
  1359	of the operators above, as well as lemmas used  by the Java and Haskell backend
  1360	to simplify expressions of sort `Int`. They do not affect the semantics of
  1361	integers, merely describing additional rules that the backend can use to
  1362	simplify terms.
  1363	
  1364	```k
  1365	endmodule
  1366	
  1367	module INT-SYMBOLIC [symbolic]

  1369	  imports INT-SYMBOLIC-KORE
  1370	  imports private BOOL

  1373	  rule I +Int 0 => I [simplification]
  1374	  rule I -Int 0 => I [simplification]
  1375

  1377	  rule X   %Int N => X requires 0 <=Int X andBool X <Int N [simplification]
  1378	
  1379	  // Bit-shifts
  1380	  rule X <<Int 0 => X                    [simplification, preserves-definedness]
  1381	  rule 0 <<Int Y => 0 requires 0 <=Int Y [simplification, preserves-definedness]
  1382	  rule X >>Int 0 => X                    [simplification, preserves-definedness]
  1383	  rule 0 >>Int Y => 0 requires 0 <=Int Y [simplification, preserves-definedness]
  1384	endmodule

  1393	  rule #Ceil(@I1:Int %Int   @I2:Int) => {(@I2 =/=Int 0) #Equals true} #And #Ceil(@I1) #And #Ceil(@I2) [simplification]
  1394	  rule #Ceil(@I1:Int modInt @I2:Int) => {(@I2 =/=Int 0) #Equals true} #And #Ceil(@I1) #And #Ceil(@I2) [simplification]
  1395	  rule #Ceil(@I1:Int >>Int  @I2:Int) => {(@I2 >=Int 0)  #Equals true} #And #Ceil(@I1) #And #Ceil(@I2) [simplification]
  1396	  rule #Ceil(@I1:Int <<Int  @I2:Int) => {(@I2 >=Int 0)  #Equals true} #And #Ceil(@I1) #And #Ceil(@I2) [simplification]

  1400	  imports private K-EQUAL
  1401	  imports private BOOL

  1405	  rule [eq-int-true-left]   : {K1 ==Int K2 #Equals true}   => {K1 #Equals K2}       [simplification]
  1406	  rule [eq-int-true-rigth]  : {true #Equals K1 ==Int K2}   => {K1 #Equals K2}       [simplification]

  1461	IEEE 754 Floating-point Numbers
  1462	-------------------------------
  1463	
  1464	Provided here is the syntax of an implementation of arbitrary-precision
  1465	floating-point arithmetic in K based on a generalization of the IEEE 754
  1466	standard. This type is hooked to an implementation of floats provided by the
  1467	backend.
  1468	
  1469	The syntax of ordinary floating-point values in K consists of an optional sign
  1470	(+ or -) followed by an optional integer part, followed by a decimal point,
  1471	followed by an optional fractional part. Either the integer part or the
  1472	fractional part must be specified. The mantissa is followed by an optional
  1473	exponent part, which consists of an `e` or `E`, an optional sign (+ or -),
  1474	and an integer. The expoennt is followed by an optional suffix, which can be
  1475	either `f`, `F`, `d`, `D`, or `pNxM` where `N` and `M` are positive integers.
  1476	`p` and `x` can be either upper or lowercase.
  1477	
  1478	The value of a floating-point literal is computed as follows: First the
  1479	mantissa is read as a rational number. Then it is multiplied by 10 to the
  1480	power of the exponent, which is interpreted as an integer, and defaults to
  1481	zero if it is not present. Finally, it is rounded to the nearest possible
  1482	value in a floating-point type represented like an IEEE754 floating-point type,
  1483	with the number of bits of precision and exponent specified by the suffix.
  1484	A suffix of `f` or `f` represents the IEEE `binary32` format. A suffix of `d`
  1485	or `D`, or no suffix, represents the IEEE `binary64` format. A suffix of
  1486	`pNxM` (either upper or lowercase) specifies exactly `N` bits of precision and
  1487	`M` bits of exponent. The number of bits of precision is assumed to include
  1488	any optional `1` that precedes the IEEE 754 mantissa. In other words, `p24x8`
  1489	is equal to the IEEE `binary32` format, and `p53x11` is equal to the IEEE
  1490	`binary64` format.
  1491	
  1492	```k
  1493	module FLOAT-SYNTAX
  1494	  syntax Float [hook(FLOAT.Float)]
  1495	  syntax Float ::= r"([\\+\\-]?[0-9]+(\\.[0-9]*)?|\\.[0-9]+)([eE][\\+\\-]?[0-9]+)?([fFdD]|([pP][0-9]+[xX][0-9]+))?" [token, prec(1)]
  1496	  syntax Float ::= r"[\\+\\-]?Infinity([fFdD]|([pP][0-9]+[xX][0-9]+))?" [token, prec(3)]
  1497	  syntax Float ::= r"NaN([fFdD]|([pP][0-9]+[xX][0-9]+))?" [token, prec(3)]
  1498	endmodule
  1499	
  1500	module FLOAT
  1501	  imports FLOAT-SYNTAX
  1502	  imports private BOOL
  1503	  imports private INT-SYNTAX
  1504	```

  1548	### Float arithmetic
  1549	
  1550	You can:
  1551	
  1552	* Compute the unary negation `--Float` of a float. `--Float X` is distinct
  1553	  from `0.0 -Float X`. For example, `0.0 -Float 0.0` is positive zero.

  1629	### Floating-point comparisons
  1630	
  1631	Compute whether a float is less than or equasl to, less than, greater than or
  1632	equal to, greater than, equal, or unequal to another float. Note that
  1633	`X ==Float Y` and `X ==K Y` might yield different values. The latter should be
  1634	used in cases where you want to compare whether two values of sort `Float`
  1635	contain the same term. The former should be used when you want to implement
  1636	the `==` operator of a programming language. In particular, `NaN =/=Float NaN`
  1637	is true, because `NaN` compares unequal to all values, including itself, in
  1638	IEEE 754 arithmetic. `0.0 ==Float -0.0` is also true.

  1641	  syntax Bool ::= Float "<=Float" Float       [function, smt-hook(fp.leq), hook(FLOAT.le)]

  1678	Strings
  1679	-------
  1680	
  1681	Provided here is the syntax of an implementation of Unicode strings in K. This
  1682	type is hooked to an implementation of strings provided by the backend. The
  1683	implementation is currently incomplete and does not fully support encodings
  1684	and code points beyond the initial 256 code points of the Basic Latin and
  1685	Latin-1 Supplement blocks. In the future, there may be breaking changes to
  1686	the semantics of this module in order to support this functionality.
  1687	
  1688	The syntax of strings in K is delineated by double quotes. Inside the double
  1689	quotes, any character can appear verbatim except double quotes, backslash,
  1690	newline, and carriage return. K also supports the following escape sequences:
  1691	
  1692	* \" - the " character
  1693	* \\ - the \ character
  1694	* \n - newline character
  1695	* \r - carriage return character
  1696	* \t - tab character
  1697	* \f - form feed character
  1698	* \xFF - \x followed by two hexadecimal characters indicates a code point
  1699	  between 0x00 and 0xff
  1700	* \uFFFF - \u followed by four hexadecimal characters indicates a code point
  1701	  between 0x0000 and 0xffff
  1702	* \UFFFFFFFF - \U followed by eight hexadecimal characters indicates a code
  1703	  point between 0x000000 and 0x10ffff

  1840	### String count and replace
  1841	
  1842	You can replace one, some, or all occurrences of a string within another
  1843	string in O(N*M) time. The `replaceAll`, `replace`, and `replaceFirst` methods
  1844	are identical, except `replaceFirst` replaces exactly one ocurrence of the
  1845	string, the first occurrence. `replace` replaces the first `times` occurrences.
  1846	And `replaceAll` replaces every occurrence.
  1847	
  1848	You can also count the number of times a string occurs within another string
  1849	using `countAllOccurrences`.
  1850	
  1851	```k
  1852	  syntax String ::= "replaceAll" "(" haystack: String "," needle: String "," replacement: String ")"      [function, total, hook(STRING.replaceAll)]
  1853	  syntax String ::= "replace" "(" haystack: String "," needle: String "," replacement: String "," times: Int ")" [function, hook(STRING.replace)]
  1854	  syntax String ::= "replaceFirst" "(" haystack: String "," needle: String "," replacement: String ")"    [function, total, hook(STRING.replaceFirst)]
  1855	  syntax Int ::= "countAllOccurrences" "(" haystack: String "," needle: String ")"            [function, total, hook(STRING.countAllOccurrences)]
  1856	```

  1858	### String equality and lexicographic comparison

  1861	is less than, less than or equal to, greater than, or greater than or equal to
  1862	another according to the natural lexicographic ordering of strings.

  1935	String Buffers
  1936	--------------
  1937	
  1938	It is a well known fact that repeated string concatenations are quadratic
  1939	in performance whereas use of an efficient mutable representation of arrays
  1940	can yield linear performance. We thus provide such a sort, the `StringBuffer`
  1941	sort. Axiomatically, it is implemented below on symbolic backends using the
  1942	`String` module. However, on concrete backends it provides an efficient
  1943	implementation of string concatenation. There are three operations:
  1944	
  1945	* `.StringBuffer` creates a new `StringBuffer` with current content equal
  1946	  to the empty string.
  1947	* `+String` takes a `StringBuffer` and a `String` and appends the `String` to
  1948	  the end of the `StringBuffer`
  1949	* `StringBuffer2String` converts a `StringBuffer` to a `String`. This operation
  1950	  copies the string so that subsequent modifications to the `StringBuffer`
  1951	  will not change the value of the `String` returned by this function.
  1952	
  1953	```k
  1954	module STRING-BUFFER-IN-K [symbolic]
  1955	  imports private BASIC-K
  1956	  imports STRING
  1957	
  1958	  syntax StringBuffer ::= ".StringBuffer" [function, total]
  1959	  syntax StringBuffer ::= StringBuffer "+String" String [function, total, avoid]
  1960	  syntax StringBuffer ::= String
  1961	  syntax String ::= StringBuffer2String ( StringBuffer ) [function, total]
  1962	
  1963	  rule {SB:String +String S:String}::StringBuffer => (SB +String S)::String
  1964	  rule .StringBuffer => ""
  1965	  rule StringBuffer2String(S:String) => S
  1966	endmodule
  1967	
  1968	module STRING-BUFFER-HOOKED [concrete]
  1969	  imports private BASIC-K
  1970	  imports STRING
  1971	
  1972	  syntax StringBuffer [hook(BUFFER.StringBuffer)]
  1973	  syntax StringBuffer ::= ".StringBuffer" [function, total, hook(BUFFER.empty), impure]
  1974	  syntax StringBuffer ::= StringBuffer "+String" String [function, total, hook(BUFFER.concat), avoid]
  1975	  syntax String ::= StringBuffer2String ( StringBuffer ) [function, total, hook(BUFFER.toString)]
  1976	endmodule
  1977	
  1978	module STRING-BUFFER
  1979	  imports STRING-BUFFER-HOOKED
  1980	  imports STRING-BUFFER-IN-K
  1981	endmodule
  1982	```

  2057	### Integer and Bytes conversion
  2058	
  2059	You can convert from a `Bytes` to an `Int`. In order to do this, the endianness
  2060	and signedness of the `Bytes` must be provided. The resulting integer is
  2061	created by means of interpreting the `Bytes` as either a twos-complement
  2062	representation, or an unsigned representation, of an integer, in the specified
  2063	byte order.
  2064	
  2065	You can also convert from an `Int` to a `Bytes`. This comes in two variants.
  2066	In the first, the `length` of the resulting `Bytes` in bytes is explicitly
  2067	specified. If the `length` is greater than the highest set bit in the magnitude
  2068	of the integer, the result is padded with 0 bits if the number is positive
  2069	and 1 bits if the number is negative. If the `length` is less than the highest
  2070	bit set in the magnitude of the integer, the most-significant bits of the
  2071	integer will be truncated. The endianness of the resulting `Bytes` object
  2072	is as specified.
  2073	
  2074	In the second variant, both endianness and signedness are specified, and
  2075	the resulting `Bytes` object will be the smallest number of bytes necessary
  2076	for the resulting `Bytes` object to be convertible back to the original integer
  2077	via `Bytes2Int`. In other words, if the highest bit set in the magnitude of the
  2078	integer is N, then the byte array will be at least N+1 bits long, rounded up
  2079	to the nearest byte.
  2080	
  2081	```k
  2082	  syntax Int ::= Bytes2Int(Bytes, Endianness, Signedness) [function, total, hook(BYTES.bytes2int)]
  2083	  syntax Bytes ::= Int2Bytes(length: Int, Int, Endianness) [function, total, hook(BYTES.int2bytes)]
  2084	                 | Int2Bytes(Int, Endianness, Signedness) [function, total, symbol(Int2BytesNoLen)]
  2085	```

  2099	### Bytes update
  2100	
  2101	You can set the value of a particular byte in a `Bytes` object in O(1) time,
  2102	either with index and value as `Int` or as an `MInt`. Currently, only 64-bit
  2103	and 256-bit `MInt` types are supported. The result is `#False` if `value` is
  2104	not in the range [0..255] or if `index` is not a valid index (ie, less than

  2106

  2108	  syntax Bytes ::= Bytes "[" index: Int "<-" value: Int "]" [function, hook(BYTES.update)]
  2109	  syntax {Width} Bytes ::= Bytes "[" index: MInt{Width} "<-" value: MInt{Width} "]" [function, hook(BYTES.updateMInt)]
  2110	```

  2112	### Bytes lookup
  2113	
  2114	You can get the value of a particular byte in a `Bytes` object in O(1) time, either as an `Int` or as an `MInt`. Currently, only 64-bit and 256-bit `MInt` types are supported.
  2115	The result is `#False` if `index` is not a valid index (see above).
  2116	
  2117	```k
  2118	  syntax Int ::= Bytes "[" Int "]" [function, hook(BYTES.get)]
  2119	  syntax {Width} MInt{Width} ::= Bytes "[" MInt{Width} "]" [function, hook(BYTES.getMInt)]
  2120	```

  2122	### Bytes substring
  2123	
  2124	You can get a new `Bytes` object containing a range of bytes from the input
  2125	`Bytes` in O(N) time (where N is the length of the substring). The range
  2126	of bytes included is `[startIndex..endIndex)`. The resulting `Bytes` is
  2127	a copy and mutations to it do not affect mutations to the original `Bytes`.
  2128	Both `startIndex` and `endIndex` can be either `Int` or `MInt` values, but,
  2129	currently, only 64-bit and 256-bit `MInt` types are supported.
  2130	
  2131	```k
  2132	  syntax Bytes ::= substrBytes(Bytes, startIndex: Int, endIndex: Int) [function, hook(BYTES.substr)]
  2133	  syntax {Width} Bytes ::= substrBytes(Bytes, startIndex: MInt{Width}, endIndex: MInt{Width}) [function, hook(BYTES.substrMInt)]
  2134	```
  2135	
  2136	The function is not total: `substrBytes(B, startIndex, endIndex)` is `#Bottom` if
  2137	* `startIndex <Int 0` or
  2138	* `endIndex <Int startIndex` or
  2139	* `lengthBytes(B) <Int endIndex`.

  2141	### Multiple bytes update
  2142	
  2143	You can modify a `Bytes` to return a `Bytes` which is equal to `dest` except the
  2144	`N` elements starting at `index` are replaced with the contents of `src` in O(N)
  2145	time. If `--llvm-mutable-bytes` is active, this will not create a new `Bytes`
  2146	object and will instead modify the original on concrete backends. The result is
  2147	`#False` if `index` + `N` is not a valid index. This function accepts both
  2148	`Int` and `MInt` values for `index` and `N`. Currently, only 64-bit and
  2149	256-bit `MInt` types are supported.
  2150	
  2151	```k
  2152	  syntax Bytes ::= replaceAtBytes(dest: Bytes, index: Int, src: Bytes) [function, hook(BYTES.replaceAt)]
  2153	  syntax {Width} Bytes ::= replaceAtBytes(dest: Bytes, index: MInt{Width}, src: Bytes) [function, hook(BYTES.replaceAtMInt)]
  2154	```
  2155	
  2156	### Multiple bytes update
  2157	
  2158	You can modify a `Bytes` to return a `Bytes` which is equal to `dest` except the
  2159	`count` bytes starting at `index` are replaced with `count` bytes of value
  2160	`Int2Bytes(1, v, LE/BE)` in O(count) time. This does not create a new `Bytes`
  2161	object and will instead modify the original if `--llvm-mutable-bytes` is active.
  2162	This will throw an exception if `index` + `count` is not a valid index. The
  2163	acceptable range of values for `v` is -128 to 127. This will throw an exception
  2164	if `v` is outside of this range. This is implemented only for the LLVM backend.
  2165

  2312	* `==K` - the equality between two terms. Returns `true` if they are equal
  2313	  and `false` if they are not equal.
  2314	* `#if #then #else #fi` - polymorphic conditional function. If the first
  2315	  argument evaluates to `true`, the second argument is returned. Otherwise,
  2316	  the third argument is returned. Note that this does not short-circuit on
  2317	  symbolic backends.
  2318	
  2319	```k
  2320	module K-EQUAL-SYNTAX
  2321	  imports private BOOL
  2322	  imports private BASIC-K
  2323	
  2324	  syntax Bool ::= left:
  2325	                  K "==K" K           [function, total, comm, smt-hook(=), hook(KEQUAL.eq), symbol(_==K_), group(equalEqualK)]
  2326	                | K "=/=K" K          [function, total, comm, smt-hook(distinct), hook(KEQUAL.ne), symbol(_=/=K_), group(notEqualEqualK)]
  2327	
  2328	  syntax priority equalEqualK notEqualEqualK > boolOperation mlOp
  2329	
  2330	  syntax {Sort} Sort ::= "#if" Bool "#then" Sort "#else" Sort "#fi" [function, total, symbol(ite), smt-hook(ite), hook(KEQUAL.ite)]
  2331	
  2332	endmodule
  2333	
  2334	module K-EQUAL-KORE [symbolic]
  2335	  imports private BOOL
  2336	  imports K-EQUAL-SYNTAX
  2337	
  2338	  rule K1:Bool ==K K2:Bool => K1 ==Bool K2 [simplification]
  2339	  rule {K1 ==K K2 #Equals true} => {K1 #Equals K2} [simplification]
  2340	  rule {true #Equals K1 ==K K2} => {K1 #Equals K2} [simplification]
  2341	  rule {K1 ==K K2 #Equals false} => #Not({K1 #Equals K2}) [simplification]
  2342	  rule {false #Equals K1 ==K K2} => #Not({K1 #Equals K2}) [simplification]
  2343	  rule {K1 =/=K K2 #Equals true} => #Not({K1 #Equals K2}) [simplification]
  2344	  rule {true #Equals K1 =/=K K2} => #Not({K1 #Equals K2}) [simplification]
  2345	  rule {K1 =/=K K2 #Equals false} => {K1 #Equals K2} [simplification]
  2346	  rule {false #Equals K1 =/=K K2} => {K1 #Equals K2} [simplification]
  2347	
  2348	endmodule
  2349	
  2350	module K-EQUAL
  2351	  imports private BOOL
  2352	  imports K-EQUAL-SYNTAX
  2353	  imports K-EQUAL-KORE
  2354	
  2355	  rule K1:K =/=K K2:K => notBool (K1 ==K K2)
  2356	
  2357	  rule #if C:Bool #then B1::K #else _ #fi => B1 requires C
  2358	  rule #if C:Bool #then _ #else B2::K #fi => B2 requires notBool C
  2359	
  2360	endmodule
  2361	```

  2399	I/O in K
  2400	--------
  2401	
  2402	Concrete execution in K supports I/O operations. This functionality is not
  2403	supported during symbolic execution, because symbolic execution must exist
  2404	completely free of side-effects, and I/O is an irreducible type of side effect.
  2405	However, it is useful in many cases when defining concrete execution to be able
  2406	to make reference to I/O operations.
  2407	
  2408	The design of these I/O operations is based on the POSIX standard, for the most
  2409	part. For example, the `#read` K function maps to the `read` POSIX function. We
  2410	do not at this time have a higher-level API for I/O, but this may be
  2411	implemented at some point in the future.
  2412	
  2413	I/O operations generally return either their result, or an `IOError` term
  2414	corresponding to the `errno` returned by the underlying system call.
  2415	
  2416	```k
  2417	module K-IO
  2418	  imports private LIST
  2419	  imports private STRING
  2420	  imports private INT
  2421	```

  2503	### I/O result sorts
  2504	
  2505	Here we see sorts defined to contain either an `Int` or an `IOError`, or
  2506	either a `String` or an `IOError`. These sorts are used to implement the
  2507	return sort of functions that may succeed, in which case they return a value,
  2508	or may fail, in which case their return value indicates an error and the
  2509	error indicated is returned via `errno`.
  2510	
  2511	```k
  2512	  syntax IOInt ::= Int | IOError
  2513	  syntax IOString ::= String | IOError
  2514	```
  2515	
  2516	### Opening a file
  2517	
  2518	You can open a file in K using `#open`. An optional mode indicates the file
  2519	open mode, which can have any value allowed by the `fopen` function in C.
  2520	The returned value is the file descriptor that was opened, or an error.
  2521	
  2522	```k
  2523	  syntax IOInt ::= "#open" "(" path: String ")" [function]
  2524	               | "#open" "(" path: String "," mode: String ")" [function, hook(IO.open), impure]
  2525	
  2526	  rule #open(S:String) => #open(S:String, "r+")
  2527	```
  2528	
  2529	### Get/set position in file
  2530	
  2531	You can get the current offset in a file using `#tell`. You can also seek
  2532	to a particular offset using `#seek` or `#seekEnd`. `#seek` is implemented via
  2533	a call to `lseek` with the `SEEK_SET` whence. `#seekEnd` is implemented via a
  2534	call to `lseek` with the `SEEK_END` whence. You can emulate the `SEEK_CUR`
  2535	whence by means of `#seek(FD, #tell(FD) +Int Offset)`.
  2536	
  2537	```k
  2538	  syntax IOInt ::= "#tell" "(" fd: Int ")" [function, hook(IO.tell), impure]
  2539	  syntax K ::= "#seek" "(" fd: Int "," index: Int ")" [function, hook(IO.seek), impure]
  2540	             | "#seekEnd" "(" fd: Int "," fromEnd: Int ")" [function, hook(IO.seekEnd), impure]
  2541	```
  2542	
  2543	### Read from file
  2544	
  2545	You can read a single character from a file using `#getc`. `#EOF` is returned
  2546	if you are at end-of-fie.
  2547	
  2548	You can also read up to `length` characters in a file using `#read`. The
  2549	resulting read characters are returned, which may be fewer characters than
  2550	requested. A string of zero length being returned indicates end-of-file.
  2551	
  2552	```k
  2553	  syntax IOInt ::= "#getc" "(" fd: Int ")"             [function, hook(IO.getc), impure]
  2554	  syntax IOString ::= "#read" "(" fd: Int "," length: Int ")"    [function, hook(IO.read), impure]
  2555	```
  2556	
  2557	### Write to file
  2558	
  2559	You can write a single character to a file using `#putc`. You can also write
  2560	a string to a file using `#write`. The returned value on success is `.K`.
  2561	
  2562	```k
  2563	  syntax K ::= "#putc" "(" fd: Int "," value: Int ")"      [function, hook(IO.putc), impure]
  2564	             | "#write" "(" fd: Int "," value: String ")" [function, hook(IO.write), impure]
  2565	```
  2566	
  2567	### Closing a file
  2568	
  2569	You can close a file using `#close`. The returned value on success is `.K`.
  2570	
  2571	```k
  2572	  syntax K ::= "#close" "(" fd: Int ")" [function, hook(IO.close), impure]
  2573	```
  2574	
  2575	### Locking/unlocking a file
  2576	
  2577	You can lock or unlock parts of a file using the `#lock` and `#unlock`
  2578	functions. The lock starts at the beginning of the file and continues for
  2579	`endIndex` bytes. Note that Unix systems do not actually prevent locked files
  2580	 from being read and modified; you will have to lock both sides of a concurrent
  2581	access to guarantee exclusivity.
  2582	
  2583	```k
  2584	  syntax K ::= "#lock" "(" fd: Int "," endIndex: Int ")" [function, hook(IO.lock), impure]
  2585	             | "#unlock" "(" fd: Int "," endIndex: Int ")" [function, hook(IO.unlock), impure]
  2586	```
  2587	
  2588	### Networking
  2589	
  2590	You can accept a connection on a socket using `#accept`, or shut down the
  2591	write end of a socket with `#shutdownWrite`. Note that facility is not provided
  2592	for opening, binding, and listening on sockets. These functions are implemented
  2593	in order to support creating stateful request/response servers where the
  2594	request loop is implemented using rewriting in K, but the connection
  2595	initialization is written in native code and linked into the LLVM backend.
  2596	
  2597	```k
  2598	  syntax IOInt ::= "#accept" "(" fd: Int ")" [function, hook(IO.accept), impure]
  2599	  syntax K ::= "#shutdownWrite" "(" fd: Int ")" [function, hook(IO.shutdownWrite), impure]
  2600	```

  2603	
  2604	You can get the current time in seconds since midnight UTC on January 1, 1970
  2605	using `#time`.
  2606	
  2607	```k
  2608	  syntax Int ::= "#time" "(" ")" [function, hook(IO.time), impure]
  2609	```

  2626	### Shell access
  2627	
  2628	You can execute a command using the shell using the `#system` operator. Care
  2629	must be taken to sanitize inputs to this function or security issues may
  2630	result. Note that K has no facility for reasoning about logic that happens
  2631	outside its process, so any functionality that you wish to be able to formally
  2632	reason about in K should not be implemented via the `#system` operator.
  2633	
  2634	```k
  2635	  syntax KItem ::= #system ( String ) [function, hook(IO.system), impure]

  2639	### Temporary files
  2640	
  2641	You can get a temporary file and open it atomically using the `#mkstemp`
  2642	operator. The resulting file will be closed and deleted when K rewriting ends.
  2643	For more info on the argument to `#mkstemp`, see `man mkstemp`.
  2644	
  2645	```k
  2646	  syntax IOFile ::= #mkstemp(template: String) [function, hook(IO.mkstemp), impure]
  2647	  syntax IOFile ::= IOError
  2648	                  | "#tempFile" "(" path: String "," fd: Int ")" [symbol(#tempFile)]
  2649	```
  2650	
  2651	### Deleting a file
  2652	
  2653	You can delete a file using its absolute or relative path using the `#remove`
  2654	operator. It returns `.K` on success or an `IOError` on failure.
  2655	
  2656	```k
  2657	  syntax K ::= #remove(path: String) [function, total, hook(IO.remove), impure]
  2658	```
  2659	
  2660	### Logging
  2661	
  2662	You can log information to disk using the `#logToFile` operator. Semantically,
  2663	this operator returns `.K`. However, it has a side effect that is not reasoned
  2664	about which is that `value` will be written to a uniquely-identified file
  2665	containing `name` in its name. The file is only flushed to disk when rewriting
  2666	finishes.
  2667	
  2668	```k
  2669	  syntax K ::= #logToFile(name: String, value: String) [function, total, hook(IO.log), impure, returnsUnit, symbol(#logToFile)]
  2670	```
  2671	
  2672	Strings can also be logged via the logging mechanisms available to the backend.
  2673	On the LLVM backend, this just means logging the text to standard error. On the
  2674	Haskell backend, a log message of type InfoUserLog is created with the
  2675	specified text.
  2676	
  2677	```k
  2678	  syntax K ::= #log(value: String) [function, total, hook(IO.logString), impure, returnsUnit, symbol(#log)]
  2679	```
  2680	
  2681	Terms can also be logged to standard error in _surface syntax_, rather than as
  2682	KORE using `#trace`. This operator has similar semantics to `#logToFile` (i.e.
  2683	it returns `.K`, but prints as an impure side effect). Note that calling
  2684	`#trace` is equivalent to invoking the `kprint` tool for the first term that is
  2685	logged, which requires re-parsing the underlying K definition. Subsequent calls
  2686	do not incur this overhead again; the definition is cached.
  2687	
  2688	```k
  2689	  syntax K ::= #trace(value: KItem) [function, total, hook(IO.traceTerm), impure, returnsUnit, symbol(#trace)]
  2690	             | #traceK(value: K)    [function, total, hook(IO.traceTerm), impure, returnsUnit, symbol(#traceK)]
  2691	```

  2693	### Implementation of high-level I/O streams in K
  2694	
  2695	Below is an implementation of the `stream="stdin"` and `stream="stdout"`
  2696	cell attributes in K. You should not refer to these symbols or modules directly
  2697	in your definition. It is provided only so that the K compiler can make use of
  2698	it. For more information on how to use this feature, refer to IMP++ in the K
  2699	tutorial.
  2700	
  2701	```k
  2702	  syntax Stream ::= #buffer(K)
  2703	                  | #istream(Int)
  2704	                  | #parseInput(String, String)
  2705	                  | #ostream(Int)
  2706	
  2707	endmodule
  2708	
  2709	// NOTE: DO NOT DIRECTLY IMPORT *-STREAM MODULES
  2710	// These stream modules will be automatically instantiated and implicitly imported
  2711	// into the main module when `stream` attributes appear in configuration cells.
  2712	// Only `Stream` productions and `[stream]` rules will be imported.
  2713	// The cell name will be replaced with the one of the main configuration.
  2714	
  2715	module STDIN-STREAM
  2716	  imports K-IO
  2717	  imports K-REFLECTION
  2718	  imports LIST
  2719	  imports INT
  2720	  imports BOOL
  2721	
  2722	  configuration <stdin> ListItem(#buffer($STDIN:String)) ListItem($IO:String) ListItem(#istream(#stdin)) </stdin>
  2723	
  2724	  // read one character at a time until we read whitespace
  2725	  rule [stdinGetc]:
  2726	       <stdin>
  2727	       ListItem(#parseInput(_:String, Delimiters:String))
  2728	       ListItem(#buffer(S:String => S +String chrChar({#getc(N)}:>Int)))
  2729	       ListItem("on")
  2730	       ListItem(#istream(N:Int))
  2731	       </stdin>
  2732	    requires findChar(S, Delimiters, 0) ==Int -1 // [stdin]
  2733	       [stream, priority(200)]
  2734	
  2735	  // when we reach whitespace, if it parses create a ListItem
  2736	  rule [stdinParseString]:
  2737	       <stdin>
  2738	       (ListItem(#parseInput("String", Delimiters:String)) => ListItem(S))
  2739	       ListItem(#buffer(S:String => ""))
  2740	       _:List
  2741	       </stdin>
  2742	    requires findChar(S, Delimiters, 0) =/=Int -1 // [stdin]
  2743	       [stream]
  2744	
  2745	  // a hack: handle the case when we read integers without the help of the IO server
  2746	  rule [stdinParseInt]:
  2747	       <stdin>
  2748	       (ListItem(#parseInput("Int", Delimiters:String))
  2749	       => ListItem(String2Int(substrString(S, 0, findChar(S, Delimiters, 0)))))
  2750	       ListItem(#buffer(S:String => substrString(S,findChar(S, Delimiters, 0) +Int 1, lengthString(S))))
  2751	       _:List
  2752	       </stdin>
  2753	    requires findChar(S, Delimiters, 0) =/=Int -1
  2754	       andBool lengthString(S) >Int 1 // [stdin]
  2755	       [stream]
  2756	
  2757	  rule [stdinTrim]:
  2758	       <stdin>
  2759	       ListItem(#parseInput(Sort:String, Delimiters:String))
  2760	       ListItem(#buffer(S:String => substrString(S, 1, lengthString(S))))
  2761	       _:List
  2762	       </stdin>
  2763	    requires findChar(S, Delimiters, 0) =/=Int -1
  2764	       andBool Sort =/=String "String"
  2765	       andBool lengthString(S) <=Int 1 // [stdin]
  2766	       [stream]
  2767	
  2768	  // NOTE: This unblocking rule will be instantiated and inserted carefully
  2769	  // when necessary according to user-defined rules, since otherwise it will
  2770	  // lead to a diverging (i.e., non-terminating) transition system definition.
  2771	  // Currently, it supports only a simple pattern matching on the top of the
  2772	  // input stream cell, e.g.,
  2773	  //   rule <k> read() => V ... </k> <in> ListItem(V:Int) => .List ...  </in>
  2774	  // Non-supported rules that refer to the input stream cell in a sophisticated
  2775	  // way will get stuck in concrete execution mode with real IO enabled (i.e.,
  2776	  // under `--io on` option), while they will still work in symbolic execution
  2777	  // mode or concrete execution mode with real IO disabled (i.e., under `--io
  2778	  // off`, `--search`, or `--debug` options).
  2779	  //
  2780	  // TODO: More patterns need to be supported as well. In that case, we need to
  2781	  // have a way to specify such patterns.
  2782	  rule [stdinUnblock]:
  2783	       <stdin>
  2784	         (.List => ListItem(#parseInput(?Sort:String, ?Delimiters:String)))
  2785	         ListItem(#buffer(_:String))
  2786	         ...
  2787	       </stdin>
  2788	
  2789	  /*
  2790	  syntax Stream ::= "#noIO"

  2869	Machine Integers
  2870	----------------
  2871	
  2872	Provided here is an implementation of arbitrarily large fixed-precision binary
  2873	integers in K. This type is hooked to an implementation of integers provided
  2874	by the backend, and in particular makes use of native machine integers for
  2875	certain sizes of integer. For arbitrary-precision integers, see the `INT`
  2876	module above.
  2877	
  2878	The syntax of machine integers in K is the same as arbitrary-precision integers
  2879	(i.e., an optional sign followed by a sequence of digits) except that machine
  2880	integers always end in a suffix `pN` where `N` is an integer indicating the
  2881	width in bits of the integer. The `MInt` sort is parametric, and this is
  2882	reflected in the literals. For example, the sort of `0p8` is `MInt{8}`.
  2883	
  2884	```k
  2885	module MINT-SYNTAX
  2886	  /*@\section{Description} The MInt implements machine integers of arbitrary
  2887	   * bit width represented in 2's complement. */
  2888	  syntax {Width} MInt{Width} [hook(MINT.MInt)]
  2889	
  2890	  /*@ Machine integer of bit width and value. */
  2891	  syntax {Width} MInt{Width} ::= r"[\\+\\-]?[0-9]+[pP][0-9]+" [token, prec(2), hook(MINT.literal)]
  2892	endmodule
  2893	
  2894	module MINT
  2895	  imports MINT-SYNTAX
  2896	  imports private INT
  2897	  imports private BYTES
  2898	  imports private BOOL
  2899	```
  2900	
  2901	### Bitwidth of MInt
  2902	
  2903	You can get the number of bits of width in an MInt using `bitwidthMInt`.
  2904	
  2905	```k
  2906	  syntax {Width} Int ::= bitwidthMInt(MInt{Width})   [function, total, hook(MINT.bitwidth)]
  2907	```
  2908	
  2909	### Int and MInt conversions
  2910	
  2911	You can convert from an `MInt` to an `Int` using the `MInt2Signed` and
  2912	`MInt2Unsigned` functions. an `MInt` does not have a sign; its sign is instead
  2913	reflected in how operators interpret its value either as a signed integer or as
  2914	an unsigned integer. Thus, you can interpret a `MInt` as a signed integer witth
  2915	`MInt2Signed`, or as an unsigned integer respectively using `MInt2Unsigned`.
  2916	
  2917	You can also convert from an `Int` to an `MInt` using `Int2MInt`. Care must
  2918	be given to ensure that the sort context where the `Int2MInt` operator appears
  2919	has the correct bitwidth, as this will influence the width of the resulting
  2920	`MInt`.
  2921	
  2922	```k
  2923	  syntax {Width} Int ::= MInt2Signed(MInt{Width})     [function, total, hook(MINT.svalue)]
  2924	                       | MInt2Unsigned(MInt{Width})     [function, total, hook(MINT.uvalue), smt-hook(bv2int)]
  2925	
  2926	  syntax {Width} MInt{Width} ::= Int2MInt(Int) [function, total, hook(MINT.integer), smt-hook(int2bv)]
  2927	```
  2928	
  2929	### Mint and Bytes conversion
  2930	You can convert from an `MInt` to a `Bytes` using the `MInt2Bytes` function.
  2931	Currently we only support converting `MInt`s of width 256 to `Bytes` in a Big Endian format.
  2932	```k
  2933	  syntax {Width} Bytes ::= MInt2Bytes(MInt{Width}) [function, total, hook(MINT.MInt2bytes)]
  2934	  syntax {Width} MInt{Width} ::= Bytes2MInt(Bytes) [function, total, hook(MINT.bytes2MInt)] 
  2935	```
  2936	
  2937	### MInt min and max values
  2938	
  2939	You can get the minimum and maximum values of a signed or unsigned `MInt`
  2940	with az specified bit width using `sminMInt`, `smaxMInt`, `uminMInt`, and
  2941	`umaxMInt`.
  2942	
  2943	```k
  2944	  syntax Int ::= sminMInt(Int)    [function]
  2945	               | smaxMInt(Int)    [function]
  2946	               | uminMInt(Int)    [function]
  2947	               | umaxMInt(Int)    [function]
  2948	  rule sminMInt(N:Int) => 0 -Int (1 <<Int (N -Int 1))
  2949	  rule smaxMInt(N:Int) => (1 <<Int (N -Int 1)) -Int 1
  2950	  rule uminMInt(_:Int) => 0
  2951	  rule umaxMInt(N:Int) => (1 <<Int N) -Int 1
  2952	```
  2953	
  2954	### MInt bounds checking
  2955	
  2956	You can check whether a specified `Int` will be represented in an `MInt`
  2957	with a specified `width` without any loss of precision when interpreted as
  2958	a signed or unsigned integer using `soverflowMInt` and `uoverflowMInt`.
  2959	
  2960	```k
  2961	  syntax Bool ::= soverflowMInt(width: Int, Int)   [function]
  2962	                | uoverflowMInt(width: Int, Int)   [function]
  2963	  rule
  2964	    soverflowMInt(N:Int, I:Int)
  2965	  =>
  2966	    I <Int sminMInt(N) orBool I >Int smaxMInt(N)
  2967	  rule
  2968	    uoverflowMInt(N:Int, I:Int)
  2969	  =>
  2970	    I <Int uminMInt(N) orBool I >Int umaxMInt(N)
  2971	```
  2972	
  2973	### MInt arithmetic
  2974	
  2975	You can:
  2976	
  2977	* Compute the bitwise complement `~MInt` of an `MInt`.
  2978	* Compute the unary negation `--MInt` of an `MInt`.
  2979	* Compute the power `^MInt` of two `MInt`s interpreted as unsigned integers.
  2980	  Currently, only 64 and 256-bits is supported.
  2981	* Compute the product `*MInt` of two `MInt`s.
  2982	* Compute the quotient `/sMInt` of two `MInt`s interpreted as signed integers.
  2983	* Compute the modulus `%sMInt` of two `MInt`s interpreted as signed integers.
  2984	* Compute the quotient `/uMInt` of two `MInt`s interpreted as unsigned
  2985	  integers.
  2986	* Compute the modulus `%uMInt` of two `MInt`s interpreted as unsigned integers.
  2987	* Compute the sum `+MInt` of two `MInt`s.
  2988	* Compute the difference `-MInt` of two `MInt`s.
  2989	* Compute the left shift `<<MInt` of two `MInt`s. The second `MInt` is always
  2990	  interpreted as positive.
  2991	* Compute the arithmetic right shift `>>aMInt` of two `MInt`s. The second
  2992	  `MInt` is always interpreted as positve.
  2993	* Compute the logical right shift `>>lMInt` of two `MInt`s. The second `MInt`
  2994	  is always interpreted as positive.
  2995	* Compute the bitwise and `&MInt` of two `MInt`s.
  2996	* Compute the bitwise xor `xorMInt` of two `MInt`s.
  2997	* Compute the bitwise inclusive or `|MInt` of two `MInt`s.
  2998	
  2999	```k
  3000	  syntax {Width} MInt{Width} ::= "~MInt" MInt{Width} [function, total, hook(MINT.not), smt-hook(bvnot)]
  3001	                               | "--MInt" MInt{Width} [function, total, hook(MINT.neg), smt-hook(bvuminus)]
  3002	                               > left:
  3003	                                 MInt{Width} "^MInt" MInt{Width} [function, total, hook(MINT.pow)]
  3004	                               | MInt{Width} "*MInt" MInt{Width} [function, total, hook(MINT.mul), smt-hook(bvmul)]
  3005	                               | MInt{Width} "/sMInt" MInt{Width} [function, hook(MINT.sdiv), smt-hook(bvsdiv)]
  3006	                               | MInt{Width} "%sMInt" MInt{Width} [function, hook(MINT.srem), smt-hook(bvsrem)]
  3007	                               | MInt{Width} "/uMInt" MInt{Width} [function, hook(MINT.udiv), smt-hook(bvudiv)]
  3008	                               | MInt{Width} "%uMInt" MInt{Width} [function, hook(MINT.urem), smt-hook(bvurem)]
  3009	                               > left:
  3010	                                 MInt{Width} "+MInt" MInt{Width} [function, total, hook(MINT.add), smt-hook(bvadd)]
  3011	                               | MInt{Width} "-MInt" MInt{Width} [function, total, hook(MINT.sub), smt-hook(bvsub)]
  3012	                               > left:
  3013	                                 MInt{Width} "<<MInt" MInt{Width} [function, hook(MINT.shl), smt-hook(bvshl)]
  3014	                               | MInt{Width} ">>aMInt" MInt{Width} [function, hook(MINT.ashr), smt-hook(bvashr)]
  3015	                               | MInt{Width} ">>lMInt" MInt{Width} [function, hook(MINT.lshr), smt-hook(bvlshr)]
  3016	                               > left:
  3017	                                 MInt{Width} "&MInt" MInt{Width} [function, total, hook(MINT.and), smt-hook(bvand)]
  3018	                               > left:
  3019	                                 MInt{Width} "xorMInt" MInt{Width} [function, total, hook(MINT.xor), smt-hook(bvxor)]
  3020	                               > left:
  3021	                                 MInt{Width} "|MInt" MInt{Width} [function, total, hook(MINT.or), smt-hook(bvor)]
  3022	```

  3024	### MInt comparison
  3025	
  3026	You can compute whether one `MInt` is less than, less than or equal to, greater
  3027	than, or greater than or equal to another `MInt` when interpreted as signed
  3028	or unsigned integers. You can also compute whether one `MInt` is equal to or
  3029	unequal to another `MInt`.
  3030	
  3031	```k
  3032	  syntax {Width} Bool ::= MInt{Width} "<sMInt" MInt{Width} [function, total, hook(MINT.slt), smt-hook(bvslt)]
  3033	                        | MInt{Width} "<uMInt" MInt{Width} [function, total, hook(MINT.ult), smt-hook(bvult)]
  3034	                        | MInt{Width} "<=sMInt" MInt{Width} [function, total, hook(MINT.sle), smt-hook(bvsle)]
  3035	                        | MInt{Width} "<=uMInt" MInt{Width} [function, total, hook(MINT.ule), smt-hook(bvule)]
  3036	                        | MInt{Width} ">sMInt" MInt{Width} [function, total, hook(MINT.sgt), smt-hook(bvsgt)]
  3037	                        | MInt{Width} ">uMInt" MInt{Width} [function, total, hook(MINT.ugt), smt-hook(bvugt)]
  3038	                        | MInt{Width} ">=sMInt" MInt{Width} [function, total, hook(MINT.sge), smt-hook(bvsge)]
  3039	                        | MInt{Width} ">=uMInt" MInt{Width} [function, total, hook(MINT.uge), smt-hook(bvuge)]
  3040	                        | MInt{Width} "==MInt" MInt{Width} [function, total, hook(MINT.eq), smt-hook(=)]
  3041	                        | MInt{Width} "=/=MInt" MInt{Width} [function, total, hook(MINT.ne), smt-hook(distinct)]
  3042	```

  3044	### MInt min/max
  3045	
  3046	You can compute the signed minimum `sMinMInt`, the signed maximum `sMaxMInt`,
  3047	the unsigned minimum `uMinMInt`, and the unsigned maximum `uMaxMInt` of two
  3048	`MInt`s.
  3049	
  3050	```k
  3051	  syntax {Width} MInt{Width} ::= sMaxMInt(MInt{Width}, MInt{Width}) [function, total, hook(MINT.smax), smt-hook((ite (bvslt #1 #2) #2 #1))]
  3052	                               | sMinMInt(MInt{Width}, MInt{Width}) [function, total, hook(MINT.smin), smt-hook((ite (bvslt #1 #2) #1 #2))]
  3053	                               | uMaxMInt(MInt{Width}, MInt{Width}) [function, total, hook(MINT.umax), smt-hook((ite (bvult #1 #2) #2 #1))]
  3054	                               | uMinMInt(MInt{Width}, MInt{Width}) [function, total, hook(MINT.umin), smt-hook((ite (bvult #1 #2) #1 #2))]
  3055	```
  3056	
  3057	### MInt to MInt conversion
  3058	
  3059	You can convert an `MInt` of one width to another width with `roundMInt`.
  3060	The resulting `MInt` will be truncated starting from the most significant bit
  3061	if the resulting width is smaller than the input. The resulting `MInt` will be
  3062	zero-extended with the same low-order bits if the resulting width is larger
  3063	than the input.
  3064	
  3065	```k
  3066	  syntax {Width1, Width2} MInt{Width1} ::= roundMInt(MInt{Width2}) [function, total, hook(MINT.round)]
  3067	  syntax {Width1, Width2} MInt{Width1} ::= signExtendMInt(MInt{Width2}) [function, total, hook(MINT.sext)]
  3068	```
