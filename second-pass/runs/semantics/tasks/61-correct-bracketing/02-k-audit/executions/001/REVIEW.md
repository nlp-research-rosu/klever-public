theorem**, but it does not contain a reachability claim that loads, calls, or
otherwise pins the submitted `solution.mpy`. A materially wrong replacement of
the real function leaves the submitted proof unchanged and still produces
`#Top`. This is a real-program adequacy failure, not a K infrastructure failure.

Audit environment: K v7.1.337, Python 3.10.12, supplied-semantics mode. All
execution used fresh source copies under `/tmp/audit-work`; no candidate
definition, cache, trace, or compiled artifact was reused.

## 2. Program fidelity and candidate-versus-canonical checks

### Contract

On the promised domain, `brackets` is a string containing only `(` and `)`.
The canonical behavior is:

1. the running number of opens minus closes must never be negative; and
2. the final number must be zero.

Equivalently, every prefix contains at least as many `(` as `)`, and the whole
string contains equal counts. This explains why a premature close such as
`")(()"` is false even if later characters might increase the balance.

The generated Python uses the same algorithm as the canonical function. Its
extra `bracket = ""` initialization has no observable effect. On each
character, `(` increments `balance`, every other character decrements it, a
negative balance returns false immediately, and exhaustion returns
`balance == 0`.

### Translation identity

Running the trusted translator on the copied `/candidate/solution.py` produced
a file byte-identical to the submitted `solution.mpy`; both have SHA-256
`9022bba7a15313c42602d1d5dc7f84072698d274da99fa12267e5ada75508e51`.
The exact command and exit status are in
[`evidence/stage2-fidelity.log`](evidence/stage2-fidelity.log).

### Independent differential test

[`evidence/differential_test.py`](evidence/differential_test.py) independently

Stage 2 result: program fidelity passes on the intended domain.

## 4. Adequacy and real-program pinning

### What the submitted claim says

The claim at `/candidate/spec.k:10` starts in an already active function frame.
In plain language, its precondition is:

- `<k>` begins with the exact internal `#loop` for remaining string codes `S`,
  followed by the source's final `return balance == 0` and `#endcall`;
- local frame 1 already exists and contains `balance = B`, a string-valued old
  `bracket`, and a string-valued `brackets`;
- the current environment is frame 1, the caller is frame 0, and the stack
  contains the corresponding return frame;
- return and exception cells are clear, the exit code is zero, and
  `B >= 0`; and
- the heap, heap counter, globals, continuation, old loop-variable value, and
  original input codes are otherwise symbolic.

Its postcondition says that the frame has been popped, caller state restored,
and the Boolean term `correctCodes(S, B)` placed immediately before the saved
continuation. Heap and heap counter are preserved. This is result-constraining:
the result is not a fresh variable, tautology, or one-way implication.

The proof-local function at `/candidate/verification.k:10` defines
`correctCodes` structurally. Empty input tests `B == 0`; code 40 (ASCII `(`)
increments; every other code returns false at balance zero or decrements a
positive balance. Under `B >= 0`, this exactly describes the source loop.

A concrete satisfying state is:

```text
B=0, S=.IntSeq, OLD=str(.IntSeq), INPUT=.IntSeq,
GLOBALS=.Map, HEAP=.Map, HLOC=0, CONT=.K
```

with the fixed cells shown in the claim. Eight ground substitutions, including
empty input, `"("`, `"()"`, `")"`, and positive-balance internal states, agreed
between `correctCodes`, the canonical Python function, and the generated Python
function. Evidence is in
[`evidence/stage4-adequacy.log`](evidence/stage4-adequacy.log), produced by
[`evidence/claim_witnesses.py`](evidence/claim_witnesses.py).

Fresh LLVM execution of the exact copied source plus 12 assertions over normal
and boundary inputs ended with `.K`, `NoExc`, and exit code 0. The generated
configuration retains the real `correct_bracketing` closure and exact submitted
body. This confirms that the supplied semantics can execute the program, but it
does not add a theorem to the candidate. See
[`evidence/stage4-adequacy.log`](evidence/stage4-adequacy.log).

### Missing real-program connection

The claim does **not** execute the submitted program. Neither `spec.k` nor
`verification.k` contains `solution.mpy`, `correct_bracketing`, `Module(...)`,
`Call(...)`, or `#loadAll`. Their dependency chain is only:

```text
spec.k -> verification.k -> reference-semantics/semantics.k
```

The claim begins after all of these unproved operations:

- module loading and registration of the actual function body;
- lookup and call of `correct_bracketing`;
- parameter binding of the concrete input;
- `balance = 0`;
- `bracket = ""`; and
- evaluation of `Name("brackets")` into the iterator used by `#loop`.

It also never requires `S == INPUT`; `INPUT` is explicitly reported unused by
the compiler. The comment claiming that the public entry case is “its `B = 0`
instance after the two initialization assignments” is an informal assertion,
not a submitted reachability theorem.

The reviewer-authored body-sensitivity test makes the gap concrete. It inserted
an unconditional `return True` before the original body, regenerated a
byte-different MPY, and exhibited `"("` as a satisfying intended-domain input:
the canonical result is false and the mutated result is true. With no proof
artifact changed, the submitted `loop` claim still exited 0 and printed
`#Top`. Commands and outputs are in
[`evidence/stage5-body-sensitivity.log`](evidence/stage5-body-sensitivity.log);
the mutation generators are
[`evidence/make_body_mutation.py`](evidence/make_body_mutation.py) and
[`evidence/body_mutation_check.py`](evidence/body_mutation_check.py).

Stage 4 result: **FAIL**. The internal theorem is sound and result-constraining,
but it does not pin the real generated program.

### Candidate-local proof extension

`correctCodes(IntSeq, Int)` is a definitional result summary, not an
operational bridge:

- Its two rules cover the disjoint `.IntSeq` and `iCons` constructors.
- The cons rule covers every integer code and balance.
- Guards are internal Boolean conditionals, so there is no rule overlap.
- Recursion strictly decreases the `IntSeq`.
- For the claim's complete domain `B >= 0`, the equations agree with the fixed
  loop step, early-return behavior, and final equality.
- The same opaque symbol is not injected into execution. The universal loop
  claim executes fixed semantics and establishes the connection to the
  function, so this is not a circular oracle bridge.

There are no candidate-local priority rules, semantic rewrites,
simplifications, opaque primitives, or body-bypassing call rules. I do not
label either candidate-local rule unsound; consequently there is no alleged
unsound-rule false-conclusion witness to supply. The rejection is the narrower
and independently witnessed absence of an entry theorem.

## 6. Fresh non-vacuity test

The candidate supplied no `spec-vacuity.k`. The reviewer-authored mutation is
[`evidence/spec-vacuity.k`](evidence/spec-vacuity.k). It changes the
result-constraining destination from:

```text
correctCodes(S, B)
```

to:

```text
notBool (correctCodes(S, B))
```

This is demonstrably false for the satisfying ground input
`S=.IntSeq, B=0`: the loop and original destination are true, while the mutated
destination is false.

`kprove --dry-run` exited 0, proving that the mutation parsed and built against
the fresh definition. The real proof exited 1 with `WarnStuckClaimState`; its
residual explicitly requires `B == 0` to equal `notBool (B == 0)` on the empty
sequence branch. This is the expected unmet obligation, not a parser error,
timeout, missing import, or unrelated crash.

## 7. Proven versus assumed accounting

### Formally established

Conditional on the supplied K semantics and K toolchain, the successful
reachability proof establishes this partial-correctness statement:

> For every remaining code sequence `S` and every nonnegative balance `B`, if
> execution starts at the exact submitted internal `#loop` state and reaches
> the specified return configuration, it returns `correctCodes(S, B)`, restores
> the caller/frame cells stated in the claim, and preserves the framed cells.

The claim is universal over `S`, `B`, continuation, globals, old loop variable,
input field, heap, and heap counter. Its false-result mutation confirms that
the returned Boolean matters.

It does **not** establish:

- that `solution.mpy` is loaded;
- that `correct_bracketing` resolves to the submitted body;
- that a call binds the public input to frame 1;
- that the two initialization assignments reach `B=0`;
- that the loop iterator `S` is the called input;
- or the public theorem `correct_bracketing(brackets) == correctCodes(codes,
  0)`.

### Trust ledger

1. **K implementation and built-in domains.** K v7.1.337, its Haskell/LLVM
   backends, and the imported `INT`, `BOOL`, `STRING`, `MAP`, `LIST`,
   `K-EQUAL`, and related hooks are trusted. They affect all machine-checking.
   This is the normal low-level proof-tool boundary.
2. **Supplied MPY semantics.** The byte-identical
   `/reference/reference-semantics` is the fixed language model selected by the
   task. The complete inventory records every declaration and rule. For this
   theorem, the relevant subset models unbounded integers, ASCII parentheses,
   deterministic string iteration, scope writes, loop control, return, and
   frame popping. This is acceptable for the intended input domain.
3. **Unused opaque/total primitives.** Every such symbol is listed in Stage 5.
   They are imported but do not influence control, state, result, or
   postcondition here. Their presence is therefore acceptable but not evidence
   about other programs.
4. **Trusted translator.** `/reference/py2mpy.py` is trusted as the Python-to-MPY
   bridge. Byte identity proves that the submitted MPY is exactly what that
   translator emits for the candidate source; it does not prove translator
   correctness in general.
5. **`correctCodes` mathematics.** Its recursive equations are
   reviewer-audited ordinary mathematics, and the K loop claim universally
   connects the fixed internal execution to them. The additional bridge from
   `correctCodes(S,0)` to the English bracketing property is an informal
   induction, supported but not proved by the differential data.
6. **Python and concrete-execution evidence.** The 8,610-case differential
   test, 12 K smoke assertions, and eight claim substitutions are empirical
   bridges only. They support implementation/intent alignment over the tested
   values and do not replace the reachability proof.
7. **Missing entry bridge.** The candidate informally assumes that the internal
   claim is reached from the real function call after initialization. This
   boundary is illegitimate for the requested theorem because it is exactly
   the program-pinning obligation. The wrong-body witness shows that the proof
   is insensitive to the submitted body.

### Final decision

The fresh `#Top` and failed false-result mutation make the internal loop lemma
credible. Nevertheless, a proof of that detached state is not a proof of the
real generated program. The absence of any entry claim, together with the
successful proof after a materially wrong body mutation, meets the decision
rule for a substituted/unpinned program.

VERDICT: FAIL
LEGITIMACY: NOT_LEGIT
