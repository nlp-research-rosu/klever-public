# Independent adversarial audit: 61-correct-bracketing

## Executive conclusion

The source-only reconstruction establishes a legitimate, result-constraining
partial-correctness theorem about the submitted translated program. The loop
claim closes independently; the end-to-end claim closes when that separately
proved claim is selected and trusted as its lemma; every ground example closes;
and the full claim set closes. A fresh false result mutation builds and then
fails at the reachable wrong Boolean. The submitted `solution.mpy` is
byte-identical to output regenerated by the trusted translator, and the
`solutionProgram` term used by the proof parses to exactly that constructor AST.

The qualification is evidence/modeling scope, not a false theorem on the
intended domain. The generated K semantics is a small audited model rather than
a machine-checked refinement of CPython; it pre-binds the loop variable even
for an empty iterable, although that local binding cannot affect this program's
claimed return value. Also, `bracketSpec` is declared globally `[total]` while
the negative-depth/non-opening case is uncovered. Every theorem use starts at
nonnegative depth and preserves that condition, so the uncovered case cannot
affect claim closure; a reviewer probe demonstrates a stuck term, not a false
equation or false result. The ordinary-mathematical bridge from `bracketSpec`
and the generated semantics to the prompt/canonical Python behavior is
supported by static analysis and finite differential evidence, but it is not a
separate machine-checked refinement theorem.

## 2. Program fidelity and candidate-versus-canonical checks

### Natural-language and trusted-reference contract

The trusted prompt restricts `brackets` to strings containing only `(` and `)`.
Together with the examples and trusted canonical implementation, the required
result is the standard well-bracketing predicate:

1. no prefix may contain more closing than opening brackets; and
2. the final numbers of opening and closing brackets must be equal.

The trusted canonical implementation maintains a depth, rejects immediately
after a closing bracket makes it negative, and finally checks `depth == 0`.
The candidate maintains the same unmatched-opening count, but checks
`count == 0` immediately before consuming a closing bracket. On the intended
domain these branch placements are equivalent: a positive count decrements
without becoming negative, while a zero count rejects.

### Translation identity

The trusted translator was run from the scratch directory:

```text

```

It exited 0 (`evidence/02_regenerate_mpy.log`). `cmp -l
regenerated-solution.mpy solution.mpy` also exited 0 with no output
(`evidence/03_mpy_byte_identity.log`). Thus the submitted `solution.mpy` is the
trusted translation of the submitted `solution.py`, byte for byte.

### Independent Python differential test
