Rule decisions and scope
------------------------
S1 is a purpose-specific invocation harness, not general Python module/call
semantics. For the exact submitted single-function Module, it binds the two
arguments correctly and executes the submitted body. S2-S8 and S11-S21 are
ordinary deterministic small-step rules that agree with the target operations
on every reachable target state. The two comparison guards are disjoint and
exhaustive. The list-add rule has the correct left/right order.

S9-S10 agree with the target because its sole Return is the final statement.
They are not a reusable implementation of abrupt Python return: in a different
program with statements after Return, S3 would preserve and execute that
suffix. This is a documented out-of-scope generality limitation, not a false
conclusion enabled by the submitted program for any positive input.

evalPlaceholder is an internal scheduling constructor declared in Value so it
can occupy binRight's Value field. No source Expr production can construct it,
and no reachable target path returns, assigns, compares, or branches on it.

V1 and V2 are mathematically true, disjoint, and exhaustive because their
guards are P and notBool(P). V3 is an unconditional truthful definition.
Neither expected function replaces program execution; both occur only in the
destination pattern. There are no operational bridges, opaque values, helper
claims, loop claims, or oracle rules.
