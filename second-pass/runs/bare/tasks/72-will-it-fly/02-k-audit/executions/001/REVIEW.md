## 2. Program fidelity and candidate-versus-canonical checks

### Natural-language and canonical contract

For an integer list `q` and integer maximum weight `w`,
`will_it_fly(q, w)` must return true exactly when:

1. `q` is palindromic; and
2. `sum(q) <= w`.

The trusted canonical implementation first rejects `sum(q) > w`, then compares
elements from the two ends until the indices cross. The candidate implementation
is:

```python
def will_it_fly(q, w):
    return q == q[::-1] and sum(q) <= w
```

On the intended domain this is the same predicate. It has the required entry
point and no hidden state or helper binding.

## 4. Adequacy and real-program pinning

### Entry-claim meaning

The universal claim has no logical `requires` clause. Its typed domain and
initial-state requirement are:

- arbitrary finite constructor value `IS:IntList`;
- arbitrary mathematical `W:Int`; and
- the standard `<generatedCounter>` initialized to 0.

Its postcondition says the final `<k>` value is exactly
`pyBool(canFly(IS,W))`. The proof-local definitions expand this to:

```text
equalIntLists(IS, reverseInts(IS)) andBool (sumInts(IS) <=Int W)
```

That is equality with the reversed list conjoined with the weight condition.
There is no free result variable, existential result, tautology, weakened

## 7. Proven versus assumed accounting

### What the reachability proof establishes

Under the local generated semantics and imported K builtins, for every finite
`IntList` and every K `Int`, executing the exact translated submitted program
from:

```text
run(solutionProgram, pyList(IS), pyInt(W))
```

reaches exactly:

```text
pyBool(
  equalIntLists(IS, reverseInts(IS))
  andBool
  (sumInts(IS) <=Int W)
)
```

The four documented ground instances are also independently proved. This is a
partial-correctness statement. The concrete program is terminating on every
finite formal input, but termination is not needed to overstate the
reachability theorem.

programs using side-effecting/exceptional right operands of `and`. Those are
outside the formal `IntList`/`Int` entry domain and outside the submitted body.
The concrete and differential tests are finite support for the audited bridge,
not a universal replacement for the successful symbolic proof.
