# Independent adversarial audit: 113-odd-count

This review treats every artifact in `/candidate` as untrusted evidence. I
reconstructed the proof from source with K v7.1.293, used only the trusted
mounted prompt, canonical implementation, translator, and supplied semantics
as baselines, and performed all builds and mutations in
`/tmp/audit-work/reconstruction`.

Headline decision: **PASS / LEGIT**. The candidate proves a
result-constraining partial-correctness claim about the submitted translated
program. Its three operational proof rules have independently reconstructed
connection theorems in definitions that exclude the rule being justified.
The proof is sensitive both to the program body and to a false observable
result.

## 2. Program fidelity and candidate-versus-canonical checks

### Natural-language contract

The trusted prompt requires a function on a finite list of strings, each
containing only decimal digits. For each input string, it returns, in the same
position, the sentence

```text
the number of odd elements Nn the strNng N of the Nnput.
```

where every `N` is the number of odd digits in that input string. Empty lists
and empty strings are within the stated domain.

The trusted canonical implementation converts each character to an integer
and counts those with remainder one modulo two. The submitted
`solution.py` instead adds `str.count` results for `"1"`, `"3"`, `"5"`,
`"7"`, and `"9"`. On digit-only strings these algorithms are equivalent:
those five characters are exactly the odd decimal digits. The candidate
preserves order, emits one result per input element, and uses the exact
required sentence.

### Trusted retranslation

In scratch I ran:

```text
python3 py2mpy.py solution.py > regenerated-solution.mpy
cmp -s regenerated-solution.mpy solution.mpy
```

Both files have SHA-256
`214486506f85a780eac0ecaad27b996df30e084ff84aaba4557fb31ed39099e6`;
translation and comparison both exited zero. Thus the submitted
`solution.mpy` is byte-identical to a fresh translation with the trusted
translator. See `evidence/04-translation-identity.log`.

### Independent differential reconstruction

The exact scope was:

### Operational bridge audit

There are exactly three priority-40 proof-local operational rules.

**Initial body bridge (`verification.k:156`).** It accepts only the exact
submitted body followed by the exact residual loop, `Return(result)`, and
`#endcall`. It fixes environment 1, exact builtins/module/function scopes, an
initial local map without old count fields, scope/heap counters, heap location
zero, the exact single call frame, normal return/exception/exit states, and a
valid digit string. It reads `digits` and `result`; writes `count`,
`count_text`, and one appended heap element; and preserves the remaining loop
and all framed cells. `CONNECTION-SPEC.initial-body-step` proves that same
transition under `VERIFICATION-BASE`, where the bridge is absent.

**Steady body bridge (`verification.k:192`).** It has the same complete
continuation and cell footprint, but requires and overwrites existing count
fields. Its initial and steady map shapes are disjoint. The corresponding
fixed-semantics claim is `CONNECTION-SPEC.body-step`, also proved with both
body rules absent.

For both body bridges, the proof claim spells the valid value as `str(CS)`;
the operational guard `digitString(V)` entails that same constructor case.
The bridge's builtins equality and every state cell are at least as narrow as
the connection theorem. There is no arbitrary continuation frame.

**Whole-loop bridge (`verification.k:230`).** It accepts only the exact
remaining list loop followed by the exact return/endcall sequence, exact
callee scopes and frame, heap location zero, allocation counters, and normal
control states. It summarizes the remaining suffix, returns the actual
`result` reference, deletes the function scope, restores environment and
scope location, and pops the exact frame. `LOOP-SPEC.outer-loop` proves the
identical transition using the connected body rules while this whole-loop
rule is absent.

The initial program loop does not yet have `digits`, `count`, and
`count_text`; therefore the whole-loop rule cannot improperly skip the first
iteration. Nonempty input first uses the connected initial body step, after
which the whole-loop invariant applies to the remaining suffix. Empty input
uses the fixed iterator/return behavior.

The two reconstructed continuation claims place an observable sentinel after
the body. Since neither exact bridge admits that suffix, fixed execution
preserves the sentinel both with and without bridge modules
(`evidence/16-prove-continuation-base.log` and
`evidence/17-prove-continuation-extended.log`).

parser error, missing import, timeout, unrelated crash, or unreachable
mutation. See `evidence/25-false-mutation-proof.log`.

This is direct non-vacuity evidence: the successful target theorem
discriminates between the correct and an off-by-one observable result.

## 7. Proven versus assumed accounting

This is partial correctness. It is not a separate total-termination proof or
