## 2. Program fidelity and candidate-versus-canonical checks

### Natural-language contract

For a finite list of integers, `sum_product(numbers)` must return a pair whose first component is the sum of all elements and whose second component is their product. The empty identities are sum `0` and product `1`. The documented examples are:

```text
[]           -> (0, 1)
[1,2,3,4]    -> (10, 24)
```

The trusted canonical implementation initializes `sum_value = 0` and `prod_value = 1`, then performs one addition and one multiplication for every element in list order. The candidate uses the same algorithm with locals named `total`, `product`, and `number`. Its extra `number = 0` before the loop is overwritten on every nonempty iteration and is unobservable for an empty iteration; it does not alter the return value. The intended domain is finite `List[int]`, modeled by arbitrary-precision K `Int` elements.

### Trusted translation

In scratch I ran:

```bash
python3 py2mpy.py solution.py > solution.regenerated.mpy
cmp -s solution.regenerated.mpy solution.mpy
```

Both files have SHA-256 `f2eee7a44c8e45da8499e635330565dba11aa16bdbc093fd9252a3e437c39369`; the command exited 0. See [02-translation-identity.log](evidence/02-translation-identity.log). Thus the submitted `.mpy` is exactly what the trusted translator produces from the submitted Python.

### Independent differential reconstruction

The reviewer-owned [differential_test.py](evidence/differential_test.py) loads `/reference/canonical.py` and `/tmp/audit-work/solution.py` under distinct module names. It does not use the proof equations. The exact deterministic corpus is preserved in [differential-inputs.json](evidence/differential-inputs.json) and contains:

- both documented examples;

All 20,121 comparisons matched, with zero mismatches; see [02-differential.log](evidence/02-differential.log). This covers the only branch boundary (zero versus at least one loop iteration), negative and zero effects on product, integer sign/parity, and arbitrary-precision examples. It is finite evidence for the Python/canonical bridge, not a substitute for the K proof.

Stage 2 passes.

### Proof-local extension inventory and decisions

1. `IntList ::= .IntList | iList(Int,IntList)` is a constructor-complete representation of finite integer lists. It introduces no oracle or state.

2. `intVals(.IntList) => .ValSeq` and `intVals(iList(I,R)) => vCons(I,intVals(R))` are disjoint, exhaustive, constructor-preserving, and structurally decreasing. They define the input embedding and do not skip program execution.

3. `#iterNext(list(intVals(.IntList))) => #iterDone` is exactly the composition of the `intVals` base equation with supplied `MPY-LIST` iteration. The only affected cell is `<k>`.

4. `#iterNext(list(intVals(iList(I,R)))) => #iterYield(I,list(intVals(R)))` is the corresponding exact cons composition. The empty/cons guards are constructor-disjoint and exhaustive. If the inner `intVals` equation fires before either priority rule, the supplied iterator rule reaches the same RHS, so the overlap agrees.

5. The exact `For(Name("number"),Name("numbers"),BODY)` bridge applies only in a closed plain local frame where `numbers = list(intVals(XS))` and the other exact program locals exist. Fixed execution performs a pure local lookup, obtains that same list value, then uses `For(T,OBJ,B) => #loop(OBJ,T,B)`. The bridge reads `<env>/<scopes>`, changes only `<k>`, preserves every other cell, binding, body, and continuation, and has the same outcome. It does not execute or summarize the loop body.

6. The exact `Return(TupleExpr(total,product))` bridge applies only in a closed plain local frame with integer accumulators and `noRet`. Fixed execution looks up `total` then `product` left-to-right, builds the two-element tuple, and applies supplied `Return(V) ~> _ => #pop` while setting `retV(V)`. The bridge reads `<env>/<scopes>`, writes exactly `<k>/<ret>`, and leaves supplied `#pop` to restore environment, remove the scope, restore `scopeLoc`, and continue. It preserves binding, evaluation order, control, and the full state footprint.

7. `sumFrom` and `productFrom` are `[function,total]` only over `IntList`. Their base/cons equations are disjoint, exhaustive, and structurally decreasing. They are the literal left folds performed by the two real assignments. They constrain the result but never replace those assignments.

There are no proof-local simplifications, opaque symbols, unchecked mathematical lemmas, result oracles, call interceptions, or rules that rewrite the loop body to an answer. All four priority bridges either compose pure fixed-semantics steps or agree with the path obtained by first reducing `intVals`.
